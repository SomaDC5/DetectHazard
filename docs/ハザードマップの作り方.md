# ハザードマップの作り方（QGIS で開ける GeoTIFF）

学習済みモデルを指定すると、県全体のタイルを貼り合わせて1枚の GeoTIFF にする。
**学習は不要。重みがあれば作れる。**

実装は `analysis/run_hazard_map.py`。

---

## 0. いちばん短い例

```bash
conda activate dc5

# 単体モデル
python analysis/run_hazard_map.py --conditions AttentionUNet_SAM_APM --region shimane

# アンサンブル（ensembles.yaml の名前）
python analysis/run_hazard_map.py --ensemble Ens_InputDiverse4 --region shimane
```

できたファイルを QGIS にドラッグするだけで開く。座標系（EPSG:6668 / JGD2011）が
入っているので、他の地図と重ねられる。

---

## 1. 何を指定できるか

| | 書き方 | いつ使うか |
|---|---|---|
| **単体モデル** | `--conditions <条件名>` | 1つのモデルの地図。`metrics.csv` と値が一致する |
| **アンサンブル（定義済み）** | `--ensemble <名前>` | `ensembles.yaml` にあるもの。しきい値も定義から読む |
| **その場の組み合わせ** | `--conditions A B C` | 定義せずに試す。重みは `--weights 2 1 1` |

```bash
python -m dc5lib.registry      # 使える条件（重みが「あり」のもの）
python -m dc5lib.ensembles      # 定義済みのアンサンブル
```

**重みが無い条件を指定すると、推論を始める前に止まる。**

```
重みがありません: ['FinalFusion_SAM_APM_bg10']。SSD を確認してください
```

SSD 2台のどちらにあるかは `python -m dc5lib.sync status`（SSDを挿さなくても分かる）。

### その他のオプション

| オプション | 既定 | 意味 |
|---|---|---|
| `--region` | 必須 | `hiroshima` / `shimane` |
| `--no-overlap` | — | タイル1枚ずつの推論にする。**速いが境界に弱い**（下記） |
| `--prob-thr` | 0.5 | 二値化しきい値 |
| `--name` | 条件名 | 出力ファイル名に使う名前 |
| `--out-dir` | `dc5-data/cache/hazard_map/` | 出力先 |

## 2. 出力されるもの

`dc5-data/cache/hazard_map/` に3つ出る（**数十MB〜。リポジトリには入れない**）。

| ファイル | 内容 |
|---|---|
| `<名前>__<地域>.tif` | 3バンド。下の表 |
| `<名前>__<地域>__mask.tif` | 二値化（0/1、255=範囲外） |
| `<名前>__<地域>__meta.json` | 条件・重み・しきい値・画素数などの記録 |

### バンド構成（`.tif` 側）

| バンド | 内容 |
|---|---|
| 1 | 確率 0〜100（%）。255 = タイルが無い範囲 |
| 2 | 正解（警戒区域）0/1。255 = 範囲外 |
| 3 | **学習に使ったタイルか 0/1。** 255 = 範囲外 |

**バンド1を 50 でしきい値処理しても `mask.tif` と一致しない。** uint8 に落とす
過程で、確率がちょうど 0.5 の画素の扱いが変わる（4節）。
数値を評価値と比べるときは必ず `mask.tif` を使う。

### バンド3（学習フラグ）が要る理由

**広島は学習に使った県なので、県全体の地図には学習済みタイルが混ざる。**
そこだけ成績が良く見えるため、地図をそのまま「性能」として見せられない。

| 地域 | 学習に使ったタイル |
|---|---|
| 広島 | **混ざる**（バンド3で除くこと） |
| 島根 | **0 件**。学習に一切使っていないので、こちらが正味の地図 |

発表で「この精度で検出できる」と言うなら島根の地図を使う。
広島の地図を使うなら、QGIS でバンド3が1の範囲を隠す。

## 3. オーバーラップ推論（既定で有効）

タイルの境界で切れた箇所が検出できない問題への対処。
`docs/失敗の所在.md` 2節のとおり、1画素も当てられないタイルの61%は
「正解が全部タイル外周16px帯にある」。

3×3 の近傍を貼り合わせ、64px ずつずらした**9窓**で推論して、中心ほど重い
cos 窓で統合する。境界の断片が窓の中心に来るので拾える。

**この研究で最も効いた施策**（箇所F +0.047〜+0.060）。既定で有効にしてある。

`--no-overlap` を付けると1枚ずつになる。速度は約5倍違う。

| | 速度 | 1条件あたり（島根24,569枚） |
|---|---|---|
| オーバーラップ（9窓） | 約 93 tiles/s | **約4.4分** |
| `--no-overlap` | 約 440 tiles/s | 約0.9分 |

### 所要時間の目安（RTX 5080）

| 条件数 | 島根 | 広島 |
|---|---|---|
| 1 | 約5分 | 約7分 |
| 4（`Ens_InputDiverse4`） | **約20分** | 約30分 |
| 14（`Ens_AllStrong14`） | 約65分 | 約100分 |

貼り合わせと書き出しに別途30秒ほど。

## 4. 正しさの確かめ方

**地図の数値が評価値と一致することを必ず確認する。** 一致しなければ
貼り合わせか二値化がずれている。

```bash
python - <<'PY'
import rasterio, numpy as np
base = "/media/$USER/SSD-PHPU3A/dc5-data/cache/hazard_map/AttentionUNet_SAM_APM__shimane"
with rasterio.open(base + ".tif") as d: g = d.read(2)
with rasterio.open(base + "__mask.tif") as d: m = d.read(1)
v = m != 255
pred, gt = m[v] == 1, g[v] == 1
tp = int((pred & gt).sum()); fp = int((pred & ~gt).sum()); fn = int((~pred & gt).sum())
print(f"面積F {2*tp/(2*tp+fp+fn):.4f} / R {tp/(tp+fn):.4f} / P {tp/(tp+fp):.4f}")
PY
```

`--no-overlap` で作った単体モデルの地図なら、`metrics.csv` の
（region, tileset=全件, scope=通常, metric_kind=面積）と一致する。
実際に `AttentionUNet_SAM_APM` / 島根で 0.5448 / 0.5545 / 0.5354 が完全一致した。

> **オーバーラップ有効の地図は `metrics.csv` と一致しない。** あちらは
> タイル1枚の推論で測った値なので、別軸の評価になる（`run_overlap_eval.py` が
> `scope="オーバーラップ"` で記録しているほうと比べる）。

### 同点（確率ちょうど 0.5）の扱いに注意

メンバーの出力が飽和している（`docs/展望.md` 8節）ので、**意見が割れた画素の
平均確率はちょうど 0.5 になる。** メンバー数が偶数だと大量に出る。

2条件・等重み・島根での実測。

| | 画素数 |
|---|---|
| 確率が [0.49, 0.51] にある | **8,611,940**（有効画素の2.1%） |
| 「> 0.5」と「>= 50（uint8に落としたあと）」で判定が違う | **1,192,518** |

**同点の扱いだけで Recall +0.025 / Precision −0.021 動く。**
スクリプトは float の確率で `> しきい値` と判定している（評価側と同じ）。
バンド1から自分でしきい値処理すると、この分だけずれる。

## 5. 大きさと資源

| 地域 | 格子 | 画素 | 有効画素 | 実ファイル |
|---|---|---|---|---|
| 広島 | 240 × 276 | 30,720 × 35,328（1,085M） | 57.6 % | — |
| 島根 | 280 × 324 | 35,840 × 41,472（1,486M） | 27.1 % | 31〜73 MB |

uint8 + DEFLATE 圧縮 + タイル化 + 概観（2/4/8/16/32）で出すので、
**QGIS で全県表示しても軽い。**

メモリは条件数に依らない（確率を逐次に足し込む）。ただし pkl の読み込みで
数GB使うので、**上限を付けて回すと安全**。

```bash
systemd-run --user --scope -q -p MemoryMax=20G -p MemorySwapMax=0 \
  python analysis/run_hazard_map.py --ensemble Ens_InputDiverse4 --region shimane
```

**上限を高くしすぎないこと。** 31GB のマシンで 22GB を許すと、システム全体の
OOM になってデスクトップ側が巻き込まれる（実際に起きた）。18〜22GB が目安。

## 6. QGIS での見せ方

1. `.tif` をドラッグして開く
2. **プロパティ → シンボロジ** で「単バンド疑似カラー」を選び、バンド1を指定
3. 0〜100 に色を割り当てる（0=透明、50以上を赤など）
4. 0 を透明にしたいときは **透過性 → 追加のnodata値** に 0 を入れる

正解と重ねたいときは、同じ `.tif` をもう1つ読み込んでバンド2を表示する。
**広島ではバンド3が1の範囲を隠す**（学習に使ったタイル）。

`mask.tif` は0/1なので、ベクタ化（ラスタ → 変換 → ラスタのベクタ化）すれば
ポリゴンとして扱える。面積集計や既存の警戒区域シェープファイルとの
重ね合わせはそちらが楽。

## 7. つまずきやすいところ

| 症状 | 原因と対処 |
|---|---|
| `重みがありません` | その条件を学習していない、または重みが他方のSSDにある。`sync status` |
| `bg_ratio が揃っていません` | `bg10` 系と `bg_ratio=0` を混ぜている。どちらかに揃える |
| `pkl 間でタイル集合が違います` | 同上 |
| `いまは rule=mean だけ対応しています` | `ensembles.yaml` の `rule` が `median` / `max`。地図は mean のみ |
| 地図の値が `metrics.csv` と合わない | オーバーラップ有効のまま比べている（3節）。`--no-overlap` で比べる |
| バンド1をしきい値処理した値が `mask.tif` と違う | 同点の扱い（4節）。`mask.tif` を使う |
| QGIS で真っ黒 / 真っ白 | シンボロジが「単バンドグレー」のまま。疑似カラーにして 0〜100 を割り当てる |
| デスクトップごと落ちる | `MemoryMax` が高すぎる（5節） |

## 8. 作成済みのもの

| ファイル | 条件 | 面積F | 備考 |
|---|---|---|---|
| `Ens_InputDiverse4__shimane.tif` | 4条件・オーバーラップ9窓 | **0.5871** | 73MB。学習外の県なので正味の地図 |

**オーバーラップが効いている。** 同じ4条件をタイル1枚で推論したときは 0.5721
（`metrics.csv` の `Ens_InputDiverse4` / 島根 / 全件）だったので **+0.0150**。
内訳は R 0.5413 → 0.5398（ほぼ同じ）/ P 0.6067 → 0.6434（**+0.037**）。
境界で切れた断片を拾うぶん、誤検出のほうが減っている。

バンド3（学習に使ったタイル）は島根で 0 画素。確認済み。

残りは順次作成する。広島は学習タイルが混ざるので、見せるときはバンド3で除くこと。
