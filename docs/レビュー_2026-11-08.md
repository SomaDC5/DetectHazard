## 1. 重大 ── 記録を黙って上書きしうる

### 1.1 `run_eval.py --split val` がテストの記録を検証の値で置き換える

- `dc5lib/evaluate.py:144-158` の `_record` は、split に関わらず `scope="通常"` で記録する
- `record_eval` の鍵 `(condition, region, tileset, scope, metric_kind, setting)` に **split が無い**
  （split は `note` にしか残らない）
- `tools/run_eval.py:56` は `--split train/val` を受け、**記録は既定でオン**

**起きること** ── `run_eval.py X --split val` で、X のテストの行が消えて検証の値が入る。

**現状** ── 未発生。`dc5lib.evaluate` 由来の記録は広島テストの4件だけ。

**直し方の案** ── split が `test` 以外なら記録を拒む（鍵は変えない。設計書 §8）。

### 1.2 島根で記録すると、テスト1,936枚の値が「全件」（24,569枚）の行を置き換える

- `dc5lib/results.py:108` の `tileset_label("shimane")` は**常に `"全件"`** を返す
- `build_loaders(cond, "Shimane")` のテストは**警戒区域ありの 1,936 枚**
- `metrics.csv` には「島根・全件・通常・n_tiles 24569」の行が **45 件**ある ── 上書きされうる記録は実在する
- `tools/run_eval.py` の docstring が `--region Shimane` を案内している

**直し方の案** ── `evaluate` から記録するときは、実際に測った集合（`警戒のみ`）を tileset に渡す。
あるいは島根の `evaluate(record=True)` を止める。

### 7.1 **`FinalFusion_SAM_APM_BlockSplit` は config に分割が書かれていない**

いちばん重い。`audit_splits.py` に**分割の指紋**の列を足したら、

行数 14,816・`train 8914 / val 2229 / test 3673` と
`31.1` の表（学習 8,914 / 検証 2,229）に**完全に一致する。**

（`kind = str(spec.get("kind") or "random")`）。

- `build_loaders(cond, "Hiroshima")` は**学習したときと違う分割**を作る。

- `audit_splits` は「出発点と一致」と**嘘の報告**をしていた

  `run_block_split.py` の設計から出ていて、`build_loaders` を通していない。
  `metrics.csv` にこの条件の行は**0件**で、`ensemble: false` なので
  和集合にも入らない

**重みからは確かめられない** ── `best_model.pth` に素性が無い
（固定前の世代）。だから「どちらの分割で学習したか」を重みから言うことはできず、
**`31.1` の枚数と CSV の枚数が一致することが唯一の裏付け**である。

**直した**（2026-11-08。許可を得て config に `split:` を書いた）。

|---|---:|---:|
| 学習 / 検証 / テスト | 8,889 / 2,963 / 2,964 | **8,914 / 2,229 / 3,673** |

「出発点のテストのうち **2,158枚**が BlockSplit の学習か検証に入っている」。

`Train_Hiroshima_Test_Shimane_SAM_APM` は検証を取らない 8:2 で

### 7.2 分割の指紋は**計算して捨てていた**

`audit_splits.split_of` は `splits.resolve` の返りを丸ごと受け取っていた
