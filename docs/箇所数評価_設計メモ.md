## 1. なぜ面積評価より低く出ていたのか

物体検出で普通に使う「IoU でしきい値判定して 1 対 1 で対応づける」方式には、
この課題では二つの落とし穴があります。

**(1) 飲み込み** — 近接した正解を 1 つの予測がまとめて覆うと、1 対 1 では
そのうち 1 個しか TP にできず残りは FN。

**(2) IoU が構造的に上がらない** — 正解が小さいと、少しのずれで IoU が
0.3 を割ります。予測が正解より大きい場合も同じ。

実データで確認したところ、**両方とも起きていました**（Final SAM+APM・広島テスト）。

| | 値 |
|---|---|
| 正解の箇所 | 8,977 個（2,964タイル、1タイルあたり 3.03 個） |
| 2 個以上の正解を覆っている予測 | 833 個 |
| **飲み込まれた正解** | **1,803 個（20.1 %）** |
| 1 つの予測が覆う正解の最大 | 8 個 |
| 正解ごとの最良 IoU の平均 | 0.388 |

飲み込まれた正解 1,803 個について、判定がどれだけ食い違うか。

| | IoU ≥ 0.3 を通る | 被覆 ≥ 0.5 を通る |
|---|---|---|
| 飲み込まれていない（7,174個） | 56.7 % | 54.9 % |
| **飲み込まれた（1,803個）** | **37.7 %** | **89.9 %** |

飲み込まれた正解は、実際には予測にほぼ覆われている（被覆で 89.9 % 通過）のに、
IoU では 37.7 % しか通りません。**仮説どおりです。**

ただし、**飲み込みだけが原因ではありません。** 飲み込まれていない 7,174 個でも
IoU 0.3 を通るのは 56.7 % です。内訳を正解の大きさで見ると、

| 正解の大きさ | 箇所数 | 最良IoU平均 | IoU≥0.3 | 被覆≥0.5 | 飲み込まれ率 |
|---|---|---|---|---|---|
| 〜100 px | 1,984 | 0.159 | 23.4 % | 35.9 % | 12.1 % |
| 100〜300 | 3,139 | 0.334 | 49.7 % | 60.8 % | 17.5 % |
| 300〜1000 | 2,732 | 0.435 | 66.1 % | 73.5 % | 24.1 % |
| 1000〜3000 | 928 | 0.521 | 81.2 % | 81.6 % | 31.4 % |
| 3000 px〜 | 194 | 0.577 | 86.1 % | 85.6 % | 33.0 % |

**小さい箇所が効いています。** 100 px 未満が 1,984 個（22 %）あり、
そこの最良 IoU 平均は 0.159 しかありません。

なお「予測が広すぎる」については、飲み込まれていない箇所に限れば
**予測面積 / 正解面積の中央値は 1.00**（25〜75 %点 0.71〜1.34、2 倍以上は 9.8 %）でした。
全体に広く塗りすぎているわけではなく、**近接した箇所をつないでしまう場所で
局所的に広がっている**、という状況です。

## 2. 実装した 3 方式

記号：正解の箇所 g_1..g_m、予測の箇所 p_1..p_n、重なり画素数 O[i,j]。

### 被覆方式 `coverage`（推奨）

```
正解 g_i を検出した  ⇔  |g_i ∩ 予測全体| / |g_i| >= cover_gt
予測 p_j が的中した  ⇔  |p_j ∩ 正解全体| / |p_j| >= cover_pred
```

「どの予測が覆ったか」を問わないので、飲み込みで損をしません。
広く塗りすぎた予測は `cover_pred` を割って FP になるので、
塗りすぎは precision 側で罰せられます。

### IoU・多対1を許す `iou_many`

```
正解 g_i を検出した  ⇔  max_j IoU(g_i, p_j) >= iou_thr
予測 p_j が的中した  ⇔  max_i IoU(g_i, p_j) >= iou_thr
```

同じ予測が複数の正解に対応してよい。落とし穴 (1) だけ解消します。

### IoU・厳密1対1 `iou_1to1`

IoU の大きい組から貪欲に 1 対 1 で確定（COCO 流）。
**前任者の実装はこれに近いと思われます。** 比較用に残してあります。

いずれも
`箇所Recall = 検出できた正解 / 正解の箇所数`、
`箇所Precision = 的中した予測 / 予測の箇所数`、
`箇所F値 = その調和平均`。
被覆と多対1では、1 つの予測が 4 個の正解を覆うと正解側 TP は 4、予測側 TP は 1 に
なります。多対 1 を許す以上これは避けられないので、そのまま扱っています。

## 3. 実データでの結果（広島テスト 2,964 タイル）

| 条件 | 設定 | 箇所Recall | 箇所Precision | 箇所F値 | 参考：面積評価F値 |
|---|---|---|---|---|---|
| Final SAM+APM | 被覆 (0.5 / 0.3) | 0.6188 | 0.6858 | **0.6506** | 0.6727 |
| Final SAM+APM | 被覆 (0.3 / 0.3) | 0.6780 | 0.6858 | **0.6819** | |
| Final SAM+APM | 被覆 (0.5 / 0.1) | 0.6188 | 0.7193 | **0.6653** | |
| Final SAM+APM | IoU多対1 (0.3) | 0.5291 | 0.5675 | 0.5477 | |
| Final SAM+APM | IoU多対1 (0.1) | 0.6655 | 0.6798 | 0.6725 | |
| Final SAM+APM | IoU厳密1対1 (0.3) | 0.5226 | 0.5656 | **0.5432** | |
| Final SAM+APM | IoU厳密1対1 (0.1) | 0.6067 | 0.6566 | 0.6307 | |

**厳密1対1・IoU 0.3 の 0.5432 が、おそらく前任者の実装が出していた水準です。**
面積評価 0.6727 より 0.13 低く、「箇所のほうが低い」という違和感と一致します。
被覆方式に替えると 0.65〜0.68 になり、面積評価と同等以上になります。

ここで注意：**多対1を許すだけでは、ほとんど改善しません**（0.5432 → 0.5477）。
飲み込みを許しても、IoU そのものが低いままだからです。
効いているのは IoU をやめて被覆で測ること、または IoU のしきい値を 0.1 に
下げることのほうです。

3 条件の比較（被覆 0.5 / 0.3）。

| 条件 | 箇所F値 | 面積F値 | 予測/正解 箇所数比 | 飲み込まれた正解 | 予測面積/正解面積 |
|---|---|---|---|---|---|
| 単一入力 SAM のみ | 0.5386 | 0.5688 | 0.872 | 31.0 % | 2.543 |
| Final SAM+APM | 0.6506 | 0.6727 | 0.924 | 21.2 % | 1.388 |
| 拡張+Attention SAM+APM | 0.6648 | 0.6991 | 1.075 | 26.2 % | 1.595 |

単一入力は予測面積が正解の 2.54 倍で、飲み込まれ率も 31 % と最悪です。
条件どうしの順位は面積評価と変わりません。

## 4. しきい値の感度（Final SAM+APM・広島）

| パラメータ | 被覆F値 (0.5/0.3) | 厳密1対1F値 (0.3) |
|---|---|---|
| min_size = 10（既定） | 0.6506 | 0.5432 |
| min_size = 30 | 0.6717 | 0.5684 |
| min_size = 100 | 0.6996 | 0.6041 |
| 連結性 4 近傍（min_size=10） | 0.6504 | 0.5416 |

- **連結性は結果をほとんど変えません**（4 近傍でも 8 近傍でもほぼ同じ）。
- **最小サイズは効きます。** 「何画素以上を 1 箇所と数えるか」は
  評価の定義そのものなので、根拠を決めて固定する必要があります。

## 5. 決めていただきたいこと

1. **方式** — 被覆方式を既定にしてよいか。
   用途（抽出結果を見て現地調査の当たりをつける）を考えると、
   1 つの予測が本物 4 個を覆っているのは見逃しではない、という立場です。
   異論があれば IoU 多対1（0.1）も候補になります。

2. **cover_gt（正解を検出とみなす被覆率）** — 既定 0.5。
   「半分以上覆われていれば、現地に行けば見つかる」という考え方。
   0.3 まで下げると Recall が 0.619 → 0.678 になります。

3. **cover_pred（予測を的中とみなす割合）** — 既定 0.3。
   「予測した面積の 3 割以上が本物なら無駄足ではない」という考え方。
   0.1 にすると Precision が 0.686 → 0.719。

4. **min_size** — 既定 10 px。1 タイル 128×128 px に対する画素数です。
   実面積で決めるなら、タイルの地上分解能から逆算して指定し直します。

5. **タイル境界の扱い** — 現状はタイル単位で数えています。
   タイルの縁で切れた警戒区域は、隣り合うタイルで別の箇所として数えられます。
   本来は地域全体でモザイクしてから数えるべきで、`GeoInfo` があるので
   実装は可能ですが、まずはタイル単位で揃えました。ここを直すかどうか。

6. **報告する指標** — 面積評価と箇所数評価を並記する形でよいか。
   両者は測っているものが違うので、片方に置き換えるのは避けたいところです。
