## 2. 条件（`experiments/<名前>/config.yaml`）

**フォルダを1つ増やせば条件が1つ増える。** コードは触らない。

```yaml
name: FinalFusion_SAM_APM_BLD_seed2_OverlapTrain
arch: TripleEncoderUNet          # dc5lib/models.py の MODEL_CLASSES にあること
family: Final
inputs:                          # 並びが model.forward の引数の順
- {key: terrain,  source: SAM, channels: 1, field: DEM}
- {key: airphoto, source: APM, channels: 3, field: AirPhoto}
- {key: building, source: BLD, channels: 2, field: Building}
augment: false
bg_ratio: 0.0                    # >0 は build_loaders 未対応（NotImplementedError）
status: active                   # excluded にすると一覧から外れる
protocol: v3-base                # 学習した手順の世代（下表）
ensemble: true                   # false なら和集合に混ぜられない
seeded: true                     # torch.manual_seed を呼んで学習したか
split:   {kind: random, test_size: 0.2, val_size: 0.25, random_state: 42}
overlap: {max_shift: 64, seed: 42}   # **0 か無しなら素のタイルで学習する**
label: …                         # 図表に出る名前。重複すると検査で止まる
note: …                          # 何のための条件か。将来の自分のため
dataset: {Hiroshima: hiroshima_sam_apm_bld.pkl, Shimane: shimane_sam_apm_bld.pkl}
train:
  epochs: 1000
  batch_size: 32
  lr: 0.0001
  seed: 2
  early_stop_patience: 100
  loss: {type: focal_tversky, alpha: 0.7, beta: 0.3, gamma: 0.75}
  augment_params: null
```

`train:` に無い項目は `dc5lib/traincfg.py` の `DEFAULTS`
（epochs 1000 / batch 32 / lr 1e-4 / seed 42 / patience 100 /
test_size 0.2 / val_size 0.25 / random_state 42 / init_from None）。

> **`train:` に書いてよい鍵は決まっている**（2026-11-11。全条件の鍵を数えて確かめた）。
>
> | 鍵 | 読む側 |
> |---|---|
> | `DEFAULTS` の9つ（`epochs` `batch_size` `lr` `seed` `early_stop_patience` `test_size` `val_size` `random_state` `init_from`）| `traincfg.train_cfg` |
> | `loss` | `dc5lib/losses.py`。**中の鍵も損失の種類ごとに決まっている**（`losses.DEFAULTS[type]` の鍵＋`aux_lambda` `aux_stages` `use_aspp` `clamp`）。それ以外は `registry.check()` が止める |
> | `augment_params` / `model_selection` / `split` | **誰も読まない。** 当時の手順を文章で残した記述で、**値を変えても何も起きない** |
> | それ以外 | **`registry.check()` が止める**（`_check_train_keys`）|
>
> `model_selection` を「テスト」に書き換えても選択は検証F のままで、
> `train.split` の文章を直しても分割は変わらない。**分割は最上位の `split:`、
> 選択は `fit` が持つ。**

### `protocol` の値

| 値 | 意味 |
|---|---|
| `v3-base` | **いまの正解。** 基盤ノートブックか `tools/run_training.py` で学習 |
| `v2-config` | config は通るが手順がノートブック持ち |
| `v1-notebook` | 値が直書き。config が届いていない |
| `v1-blocksplit` / `v1-8:2-testselect` | 分割か選択が他と違う（`ensemble: false`）|

> **`split:` は、既定の乱数分割と違う条件では必ず書くこと**（2026-11-08）。
> `splits.resolve` は `split:` が空なら**黙って `random` に落ちる**ので、
> 書かないと `build_loaders` が**学習時と違う分割**を作る。
>
> | 条件 | 本当の分割 | config |
> |---|---|---|
> | `FinalFusion_SAM_APM_BlockSplit` | `splits/hiroshima_block_20km.csv`（8,914 / 2,229 / 3,673・分割の指紋 `dde2064b8523`）| **`split: {kind: csv, file: hiroshima_block_20km}` を書いた** |
> | `Train_Hiroshima_Test_Shimane_SAM_APM` | 8:2（**検証を取らず、テストで最良エポックを選んだ**）| **書けない。** `resolve` は `val_size=0` を扱えない |
>
> 後者は**テストだけは一致する**（`test_size=0.2` / `random_state=42` が同じなので
> `train_test_split` の1段目が同じ）。だから `split="test"` の評価は正しく、
> **`val` が架空**になる。`ensemble: false` の理由は分割ではなく**選択**である。
> ※ ノートブックの実物で1段目の呼び方を確かめてはいない（**未検査**）。
>
> **`registry.check()` が「protocol は csv 分割なのに `split:` が無い」を見る。**

### **`Condition` に無いキーを config に書くと `TypeError` で落ちる**

`registry.load_one` が `Condition(dir=..., **d)` を呼ぶため。
新しいキーを足すときは **`dc5lib/registry.py` の `Condition` に
フィールドを足してから** config に書く。既定値を付けること（古い config が通る）。

> **config を触る作業中に長い実験を走らせない。** 走っているプロセスは
> 古い `registry` を持っているので、新しいキーの config を読めず落ちる。
> 実際に事故った。

## 3. 学習・評価の入口（**これだけ呼ぶ**）

### 3.1 一本道

```python
from dc5lib.registry import get
from dc5lib.traincfg import train_cfg
from dc5lib.pipeline import build_loaders, seed_everything
from dc5lib.models import build_model_for
from dc5lib.train import fit
from dc5lib.evaluate import evaluate

cond = get(CONDITION)
cfg  = train_cfg(CONDITION)
seed_everything(cfg.seed)          # **これが無いと train.seed は何も変えない**
ld   = build_loaders(cond, "Hiroshima")
model = build_model_for(cond)
hist = fit(cond, ld, hooks={"model": model, "seeded": True})
evaluate(cond, ld, "test", record=True)    # model= は渡さない（3.3）
```

### 3.2 署名と返り

| 入口 | 署名 | 返り・要点 |
|---|---|---|
| `registry.get(name)` | → `Condition` | `.weights` / `.checkpoint` / `.in_channels` / `.pkl_for(地域dir)` / `.display()` |
| `traincfg.train_cfg(condition)` | → `TrainCfg` | `condition` は条件名でも `Condition` でもよい。`.source` に「config 由来か既定か」が入る。`.describe()`。**`DEFAULTS` に無い鍵は拾わない**（`registry.check()` が「誰も読まない鍵」を止める）|
| `pipeline.seed_everything(seed)` | | random / numpy / torch / cuda を固定 |
| `pipeline.build_loaders(cond, region="Hiroshima", batch_size=None, transform=None, num_workers=0, verbose=True)` | → `Loaders` | `.train/.val/.test`（DataLoader）・`.split`・`.fields`・`.n_all/.n_used/.n_bg/.n_allowed`・`.overlap`・`.datasets`・`.meta_split()`・`.describe()`。**`bg_ratio > 0` と1入力の条件は pkl を読む前に `NotImplementedError`** |
| `Loaders.datasets` | dict | `train` / `val` / `test` / **`all`**。**`all` は警戒区域ありの全件を素のタイルで返す**（島根の補助 9,679枚を測るため）。**`train` はオーバーラップ条件ではずらした窓を返すので、評価に使わない**（3.3）|
| `models.build_model_for(cond)` | → `nn.Module` | `cond.in_channels` から組む |
| `models.load_weights(model, path, device=...)` | | 既存の `model_state_dict` 鍵を読む |
| `train.fit(cond, loaders, device=None, hooks=None, epochs=None, weights=None, curve=None, verbose=True, overwrite=False)` | → `History` | `.best_epoch/.best_val_f1/.epochs_ran/.stopped_early/.curve/.weights`。早期終了・曲線の書き出し・最良エポックの選択を**全部持つ**。**既存の重みか曲線があると学習を始めずに止まる**（`overwrite=True` で上書き）|
| `evaluate.evaluate(cond, loaders, split="test", model=None, device=None, forward=None, thr=0.5, instance=True, verbose=True, record=False, rebuild_csv=True)` | → `Result` | `.pixel`・`.instance`・`.n_tiles`・`.describe()` |
| `evaluate.can_record_split(region, split="test")` | → (bool, 文) | **pkl を読む前**に「この地域・この split を記録できるか」。道具はこれを呼ぶ（§8 の表を自分で持たない）。**規則は書き写さず `splits.EXPECT` → `_recordable` から導く**ので、`EXPECT` に無い地域は `False`（4回目のレビュー B）|
| `evaluate.can_record(cond, loaders, split="test")` | → (bool, 文) | **`loaders` を作ったあと・学習の前**に「記録できるか」。`evaluate(record=True)` と同じ検査を例外にせず返す。**`can_record_split` は地域しか見ないので、csv 分割の条件は通ってしまう** ── 学習の入口（`run_training.py`・`templates/train.ipynb`）はこちらを呼ぶ |
| `evaluate.check_training_region_names(names, region, n_tiles=None)` | → None | 下の `check_training_region` を**構成員の全員**に掛ける。**推論の前に呼ぶ。** `n_tiles` を省くと `regions.yaml` の `subset` から決める（島根＝全件・広島＝テスト）。`analysis/` の記録の経路が呼ぶ（§8）|
| `ckpt.describe(path)` / `ckpt.meta_of(path)` | → str / dict or **None** | `None` は素性の無い古い重み |
| `splits.expected(region)` | → dict or **None** | **分割の期待値の原本**（`EXPECT`）を引く。`Hiroshima` / `hiroshima` どちらでもよい。無い地域は `None`（§4）|
| `splits.compare_expected(region, n_used, split)` | → dict | `EXPECT` と照合して**違うものだけ** `{鍵: (実際, 期待)}` を返す。**`split` に無い鍵（`n_all`）は見ない。** 照合はここだけに置く（`run_training` / `audit_splits` / `templates/train.ipynb` が呼ぶ）|
| `evaluate.check_training_region(cond, region, n_tiles)` | → None | **学習に使った地域でテスト分割以外を記録しようとしていたら `ValueError`。** `evaluate` と `analysis/run_overlap_eval.py` の両方が呼ぶ |
| `splits.is_standard(sp)` | → bool | `resolve` の返りを渡す。**`EXPECT` と比べてよい分割か**（`kind=random` かつ既定の値）|
| `splits.spec_is_standard(cond)` | → bool | 同じことを **config の宣言だけ**から見る（pkl を読む前に使える）。値の決まり方は `resolve` と同じ順（`split:` → `train:` → 既定）|
| `splits.fits_subset(cond, subset)` | → (bool, 文) | **`analysis/` の道で、その条件をそのタイル集合で測ってよいか。** `holdout`（広島の乱数テスト）は宣言が既定の乱数分割の条件だけ、`blocktest` は `split.kind == csv` の条件だけ（§5）|
| `registry.split_declaration(cond)` | → (種別, 文) | config の `split:` が実態に合っているか。種別は下の4つ |

`split_declaration` の種別

| 種別 | 意味 | `check()` |
|---|---|---|
| `None` | 問題なし | 通る |
| `"undeclared"` | **csv 分割なのに `split:` が無い。** 乱数に落ちる | **止める** |
| `"misnamed"` | `split.kind=csv` は書いてあるが、名前も protocol もブロック分割と名乗っていない。**宣言は済んでいて、問題は名前のほう** | **止める** |
| `"cannot_declare"` | 宣言できない条件（検証を取らない 8:2）。**既知として黙らせる** | 通る |

`fit` の `hooks`：`model` / `optimizer` / `forward` / `loss_fn` /
`on_epoch_end` / `seeded`。

### 3.3 **やってはいけないこと**（全部実際に踏んだ）

| してはいけない | なぜ |
|---|---|
| 学習ループを書き写す | `fit` が持つ。早期終了と曲線の書き出しを取りこぼす |
| 値をノートブックに書く | config から来る。直書きは `tools/audit_wiring.py` が落とす |
| 学習と評価を同じノートブックに入れる | 片方だけ config に直して**もう片方が直書きのまま残る**（実際に残った）|
| `allowed=None` を渡す | 検証・テストのタイルを近傍に貼ってしまう（データリーク）|
| テストで最良エポックを選ぶ | 選択は検証F。旧プロトコル3本がこれをやって `ensemble: false` になった |
| `fit` のあと `evaluate(..., model=model)` | **`fit` は最良を `model` に戻すが、二重に守るため `model=` を渡さずディスクから読む**（戻していなかった時期に最終エポックを測っていた）|
| 既存の重み・曲線を作り直す | 作り直さない方針 |
| 数字を docs に書いて記録しない | `record=True` か `--record` で `results/evals/` に入れる |
| **`evaluate(..., split="val"/"train", record=True)`** | 記録の鍵に `split` が入らないので、**テストの行を置き換える**。`record=False` にする（`ValueError` で止まる）|
| **島根で `record=True`**（テスト 1,936枚）| その枚数に**ラベルが無い**ので「島根・警戒のみ」（9,679枚の17件）を置き換える。`ValueError` で止まる（§8）|
| **`augment:` / `train.init_from:` を config に書く** | **届かない。** `fit` が `NotImplementedError` で止める（設計書 §8）|
| **`train.loss.aux_lambda` > 0 の条件を、hooks なしで `fit` に通す** | **補助損失（深層監督）は届かない。** モデルには補助ヘッドが付くが、`fit` は `return_aux=True` を渡さず損失も本体の出力にしか掛けないので、**補助ヘッドは学習されず、補助損失なしの学習になる**。`fit` が `NotImplementedError` で止める（`tools/run_training.py` は pkl を読む前に止まる）。回すなら hooks に `forward` と `loss_fn` の両方を渡す。該当は12条件で、どれも v1／v2（ノートブックの自前のループで学習）|
| **既存の重み・曲線があるのに `fit` を回す** | 曲線は開いた瞬間に消え、1エポック目で重みが上書きされる。`overwrite=True` で明示する |
| **`datasets["train"]` をつないで評価する** | オーバーラップ条件の学習用データセットは**乱数でずらした窓**を返す（`deterministic=False`・`max_shift>0`）。素のタイルの値にならず、測るたびに変わる。**`datasets["all"]` を使う。** `record=True` なら `ValueError` で止まり、`record=False` でも注意が出る（2026-11-11。`eval_shimane` のセル3がこれをやっていた）|
| **別の分割で学習した条件を `analysis/` の道で広島のテストに掛ける** | `analysis/` の道は条件の `split:` を見ず、**いつも random/42 のテスト**を作る。ブロック分割の条件を掛けると、テスト 2,964枚のうち **2,158枚**が学習か検証のタイルになる（`audit_splits` の実測）。`splits.fits_subset` が推論の前に止める |
| **config の `train:` に、読まれない鍵を書く** | 読まれるのは `traincfg.DEFAULTS` の鍵と `loss` だけ。それ以外は**黙って捨てられる**ので、打ち間違い（`batchsize`）でも既定のまま学習が走る。`registry.check()` が止める。読ませたい項目は先に `DEFAULTS` に足す（§2）|

### 3.4 モデル定義（`dc5lib/models.py`）

**層の名前と順序は変えない**（既存の重みを `strict=True` で読むため）。
新しい構造は**クラスを足して `MODEL_CLASSES` に登録する**。既存のクラスは直さない。

| 確かめたこと（2026-11-12）| 結果 |
|---|---|
| 全条件で、config から組んだモデルに重みが `strict` で入るか | 重みのある45本のうち **44本が入る**。入らないのは `Triple_UNet_SAM_APM_GEO`（`excluded`）の1本 |
| 登録してある22クラスは前向きに通るか | 全部通る（CPU・1枚・出力 `(1, 1, 128, 128)`）|
| この SSD に重みが無い条件 | 8本（`bg10_ASPPStride4`・`bg10_FullSkip` 系3本・`bg30`・`bg50`・`FullSkipSup`・`UNet_SAM_InstLoss`）|
| 重みに素性（`meta`）がある条件 | **1本だけ**（`FinalFusion_SAM_APM_BLD_seed2_OverlapTrain`）|

- **`Triple_UNet_SAM_APM_GEO` の重みは `TripleEncoderUNet` では読めない。** 重みのボトルネックは
  1536→1536、クラスは 1536→1024（クラスの docstring のとおり）。config の `arch` は
  `TripleEncoderUNet` のままなので、**この条件は推論できない**（`excluded` なので検査は見ない）
- **素性のある重みが1本しか無い**ので、素性に頼る歯止め（`union.verify` の分割の照合・
  `check_training_region`・`guard_stage2_weights` の相方）は、既存の重みの大半で
  「分からない」になる。**分割は `tools/audit_splits.py` で確かめる**
- **`aux_stages` を config に書かないと `(1, 2, 3)` になる**（`losses.aux_stages` の既定）。
  クラス側の既定が `(2,)` の構造（`SupAttn*`・`ASPP*`）では**別の構造が組まれる**ので、
  補助損失を使う条件は `aux_stages` を必ず書く（既存の条件は書いてある）。
  `aux_lambda` が 0 なら `build_model_for` は段を空にする（補助ヘッドを作らない）
- `TransUNetDual` は位置符号の数が入力 128px で決まる。`HiResAir*` は航空写真が 256px で
  来ないと `ValueError`（`*_sam_apm256.pkl` の取り違えを止める）。
  **256px の航空写真はオーバーラップ学習（`OverlapDataset` のずらした窓）と
  `run_overlap_eval.py` に通していない**（該当は `AttentionUNet_SAM_APM256` の1本。未検査）
- 補助出力（`return_aux=True`）を返すのは `DeepSup*`・`AllSkipDeepSup*`・`SupAttn*`・`ASPP*`・
  `FullSkip*`。**既定では本体の出力だけを返す**ので、推論と評価は補助の有無を気にしなくてよい
