## 1. 全体の地図

**4つの層と、その横にある定義ファイル。** 矢印は「読む」向き。

```
【定義】値だけ。手順を書かない
  experiments/<条件>/config.yaml   1フォルダ = 1条件
  regions.yaml                     地域（広島・島根）
  splits/hiroshima_block_20km.csv  ブロック分割の表
  ensembles.yaml                   旧アンサンブル（確率平均）＋ 後処理（刈り取り）
  unions/*.yaml                    新アンサンブル（和集合）
        │ 読む
        ▼
【dc5lib/】手順。ここだけが処理を持つ
  paths ─ regions ─ registry ─ traincfg      （条件と設定を読む）
  data ─ splits ─ overlap ─ inputs ─ pipeline （pkl → DataLoader）
  models ─ losses ─ instance_loss             （構造と損失）
  train ─ ckpt                                （学習・重みの素性）
  evaluate ─ instance_eval ─ results          （測る・記録する）
  ensembles ─ postprocess ─ union ─ stage2    （混ぜる・刈る）
        │ 呼ぶ
        ▼
【入口】dc5lib を順に呼ぶだけ
  tools/run_training.py   tools/run_eval.py
  templates/train.ipynb   templates/eval_shimane.ipynb   templates/union.ipynb
        │
        ▼
【analysis/】展望 42〜48 の数字を出すスクリプト
  部品（config / data / infer / instances）
  run_overlap_eval → run_overlap_prune → run_stage2_* → run_union_*
        │ 書く
        ▼
【成果物】
  <SSD>/dc5-data/weights/<条件>/best_model.pth     重み（git に載らない）
  <SSD>/dc5-data/cache/                            中間物（消してよい）
  results/curves/<条件>.csv                        学習曲線
  results/evals/*.json → results/metrics.csv       精度の記録
```

**検査の道具（`tools/check.py` ほか）は、この全部を横から見ている。**

### 覚えておく芯は1つ

**値と手順をノートブックに置かない。** 値は `config.yaml`、手順は `dc5lib/`。
レビューで迷ったら「**この値・この手順は原本が1か所か**」を問う。

## 2. 一本道 — 学習して測るまで

実装書 `3.1` の6行を、**どのファイルが何を受け取って何を返すか**で並べ直したもの。

| 順 | 呼ぶもの | ファイル | 受け取る | 返す | 中で読む先 |
|---|---|---|---|---|---|
| 1 | `registry.get(名前)` | `dc5lib/registry.py` | 条件名 | `Condition` | `experiments/<名前>/config.yaml`・`paths`・`regions` |
| 2 | `traincfg.train_cfg(名前)` | `dc5lib/traincfg.py` | 条件名 | `TrainCfg` | `registry`（config の `train:`）。無い項目は `DEFAULTS` |
| 3 | `pipeline.seed_everything(seed)` | `dc5lib/pipeline.py` | シード | — | — |
| 4 | `pipeline.build_loaders(cond, 地域)` | `dc5lib/pipeline.py` | `Condition` | `Loaders` | `data`（pkl を読む）→ `splits.resolve`（分割）→ `overlap`（近傍）→ `inputs`（入力の並び）|
| 5 | `models.build_model_for(cond)` | `dc5lib/models.py` | `Condition` | `nn.Module` | `losses`（補助損失の設定）・`registry` |
| 6 | `train.fit(cond, ld, hooks=…)` | `dc5lib/train.py` | `Condition`・`Loaders` | `History` | `traincfg`・`losses.build_loss`・`ckpt.save`・`paths`（重みと曲線の置き場）|
| 7 | `evaluate.evaluate(cond, ld, "test", record=True)` | `dc5lib/evaluate.py` | `Condition`・`Loaders` | `Result` | `models.load_weights`・`ckpt.meta_of`・`splits`・**`analysis/instances.py`**・`results.record_eval` |

**この7行を呼んでいる入口は4つ** ── `tools/run_training.py`・`tools/run_eval.py`・
`templates/train.ipynb`・`templates/eval_shimane.ipynb`。

> **`analysis/` の数字（展望 42〜48）はこの一本道を通らない。**
> `analysis/data.py` で pkl を読み、`analysis/run_overlap_eval.py` で
> オーバーラップ推論をする**別の道**である（`7.2`）。
> **どちらの道の話かを先に確かめる。**

### 一本道の中で、読んで分かったこと

| 場所 | 中身 |
|---|---|
| `build_loaders` | **pkl を読む前に止めるもの** ── `bg_ratio > 0` と1入力の条件。読んだあと、警戒区域ありのタイル（`max(Mask) >= 1`）を先・背景を後に並べ直す。**この並びが添字の前提** |
| `build_loaders` の返り | `datasets` は `train`（**ずらした窓**。オーバーラップ条件のとき）・`val`・`test`・`all`（**どれも素のタイル**）。`all` は警戒区域ありの全件 |
| `fit` | 始める前に `_guard_before_training`（既存の重みと曲線・`augment`・`init_from`）→ 損失が重みマップを要るかの検査 → **そのあとで**曲線を `"w"` で開く。最良の検証F のたびに `ckpt.save`。終わったら**最良の重みを `model` に戻す** |
| `evaluate` | `record=True` なら推論の前に `_guard_record`（split・ずらした窓・枚数とラベル・学習した地域）。`model=` が無ければ重みをディスクから読む。箇所評価は `analysis/instances.py` を呼ぶ |
| `record_eval` | 鍵 `(condition, region, tileset, scope, metric_kind, setting)` が同じ古い JSON を**消してから**書く。消す前に旧の値を出す |

### 3.8 `models.py` の地図（22クラス）

**層の名前と順序が重みとの契約**（`strict=True` で読む）。44本の重みが入ることを測った。
既存のクラスは直さず、新しい構造は**クラスを足して `MODEL_CLASSES` に登録する。**

| まとまり | クラス | 何が違うか | 使う条件 |
|---|---|---|---:|
| 土台 | `MultiEncoderUNet` | 地形（1ch）と写真（3ch）の符号化器を別に持ち、ボトルネックで連結。スキップは2本とも渡す | 19 |
| 入力の本数 | `UNet`／`TripleEncoderUNet` | 1入力／3入力（3本目のチャネル数は config から）| 1／5 |
| 融合の位置 | `EarlyFusionUNet`／`MiddleFusionUNet` | 入力で連結／各段で融合して足し戻す | 2／2 |
| ゲート | `AttentionMultiEncoderUNet` | スキップにブランチ別の Attention Gate | 3 |
| 大域の文脈 | `TransUNetDual` | ボトルネックに Transformer（**入力は 128px 固定**）| 1 |
| 監督 | `DeepSup*`／`AllSkipDeepSup*` | スキップに存在マップの補助ヘッド（1段／複数段）| 1／1 |
| 監督＋変調 | `SupAttn*`／`SupAttnPerBranch*` | 補助ヘッドの出力でスキップを `x * (1 + σ)` に変調（結合後／ブランチ別）| 1／2 |
| 文脈＋解像度 | `ASPPDeepSup*`／`ASPPStride8*`／`ASPPStride4*` | スキップに ASPP／さらにボトルネックを 16px／32px で計算 | 1／1／1 |
| 統合のしかた | `FullSkipMultiEncoderUNet` | 各デコーダ段が全スケールを受ける（UNet3+ 風）。監督と ASPP は任意 | 6 |
| 写真の解像度 | `HiResAir*`（2つ）| 写真を 256px で受けて1段畳んでから 128 に落とす | 0／1 |
| 他の族 | `SegFormerDual`／`FCNDual`／`PSPNetDual`／`DeepLabV3Dual`／`MLPDecoderDual` | 符号化器か頭を入れ替えた比較用。後ろ4つの符号化器は土台と同じ | 各1 |

**レビューで見ること**

- [ ] **既存のクラスの層の名前・順序・形を変えていないか**（変えると重みが入らなくなる。
      変えたら全条件の `load_state_dict(strict=True)` をやり直す）
- [ ] 新しいクラスを `MODEL_CLASSES` に登録したか。`forward` の引数の数が config の `inputs` と合うか
- [ ] 補助出力を返す構造なら、**既定（`return_aux=False`）で本体だけを返すか**
- [ ] 補助損失を使う条件の config に **`aux_stages` を書いたか**（書かないと `(1, 2, 3)`）
- [ ] 補助損失の条件を `fit` で回すなら、hooks に `forward` と `loss_fn` の**両方**を渡したか

## 7. 繋がりの中で注意する場所

import を機械で抜いて見えた、**レビューで見落としやすい繋がり**。
設計の良し悪しではなく、**「ここを変えるとあそこが動く」の地図**である。

### 7.1 `dc5lib/evaluate.py` は `analysis/` を読んでいる（**上向き**）

層の図では `dc5lib` が下、`analysis` が上だが、`evaluate.instance_scores` は
関数の中で `analysis/instances.py` と `analysis/run_instance_eval.py`（`SETTINGS`）を
import する。設計書 `2` の「評価ロジックを持たない」がこれである。

**レビューで見ること** ── `analysis/instances.py` か `run_instance_eval.py` の
`SETTINGS` を変える差分は、**`tools/run_eval.py` と学習後の評価の数字も変える。**

### 7.2 データを読む道が2本ある

| | 新しい道 | analysis の道 |
|---|---|---|
| pkl を読む | `dc5lib/data.py` `load_dataset` | `analysis/data.py` `load_pkl` |
| テスト分割 | `dc5lib/splits.py` `resolve` | `analysis/data.py` `hiroshima_test_indices` |
| まとめ役 | `dc5lib/pipeline.py` `build_loaders` | `analysis/data.py` `build_tileset`／`run_overlap_eval.target_tiles` |
| 使う側 | `tools/run_*`・`templates/` | `analysis/run_*`（展望 42〜48）|

**測った結果（2026-11-11）**

| 確かめたこと | 結果 |
|---|---|
| 2本の道が選ぶ広島のテスト | **同じ 2,964枚**（14,816枚に対する添字が並びまで一致）|
| `analysis/` の道が条件の `split:` を見るか | **見ない**（`target_tiles` と `build_tileset` に条件が渡らない）|
| ブロック分割の条件を広島の乱数テストに掛けると | テスト 2,964枚のうち **2,158枚**が学習か検証 |
| 乱数分割の条件をブロック分割のテストに掛けると | テスト 3,673枚のうち **2,867枚** |
| その値が記録にあるか | **無い**（`metrics.csv` にブロック分割の条件の行 0・`hiroshima_block` の行 0）|

既定の乱数分割の条件については2本は同じなので、**既存の数字は正しい。**
食い違うのは別の分割で学習した条件だけで、いまは
**`splits.fits_subset(cond, subset)` が `analysis/` の入口で止める**
（`run_overlap_eval.require_fit`・`run_overlap_prune.infer`・`config.group_by_pkl`）。
**`tools/audit_splits.py` はこの2本の違いを見ない** ── あの道具が呼ぶのは
`splits.resolve` だけである。上の漏れの枚数は、条件を2つ並べて掛けて出した。

**分割の値（`test_size 0.2`・`random_state 42`）が置いてある場所は4つ** ──
`dc5lib/traincfg.py` の `DEFAULTS`・`dc5lib/splits.py` の `STD`・
`dc5lib/data.py`・`analysis/config.py`。
`analysis/run_stage2_train.py` の `split_indices` には検証の `0.25` が直書きされている。
**分割の値を変える差分が来たら、この全部を見る**（まとめてはいない。設計書 §8）。

### 7.3 箇所評価の実装が2つある

| | `analysis/instances.py` | `dc5lib/instance_eval.py` |
|---|---|---|
| 位置づけ | **数字を出している本体** | 持ち込み用・単体で動く版。**`PRIMARY` と帯の原本** |
| 設定の表 | `run_instance_eval.py` の `SETTINGS` | `DEFAULT_SETTINGS` |
| `label_instances` の `min_size` の既定 | `0` | `10` |

**測った結果（2026-11-11）**

| 確かめたこと | 結果 |
|---|---|
| 2つの設定の表 | **同じ**（7方式・並びも一致）|
| 2つの実装が出す値 | **同じ**（合成マスク 400枚・正解 9,328 / 予測 11,824 のかたまり。7方式すべてで箇所R/P/F の差 0、かたまりの数も同じ）|
| `label_instances(` の呼び出し | すべてが最小サイズを明示している（grep）|

**どちらの実装がどの数字を出しているか**（読んだ範囲で）── `run_overlap_eval.py` の
記録は `dc5lib/instance_eval.py` の `InstanceEvaluator`、`run_overlap_prune.py` の
`score`／`full_scores` と `dc5lib/evaluate.py` は `analysis/instances.py`。
**両方から数字が出ている**ので、片方だけ直すと食い違う。
`min_size` の既定が違う（0 と 10）ので、**新しい呼び出しが既定に頼っていないか**を見る。

### 7.4 スクリプトが部品になっている

`run_overlap_eval.py` と `run_overlap_prune.py` は**それぞれ10本前後から import されている。**
「スクリプトだから自分しか使わない」と思って引数や返りを変えると、下流が落ちる。
`6.1` の表に載っているファイルの差分は、**「読まれる元」を grep してから読む。**

### 7.5 `registry` と `models` は互いを読む

どちらも**関数の中で** import しているので循環では落ちない。
ただし**ファイルの先頭に import を移す差分**が来たら落ちる。

### 7.6 アンサンブルは2系統

| | 旧：確率を混ぜる | 新：和集合 |
|---|---|---|
| 定義 | `ensembles.yaml` | `unions/*.yaml` |
| モジュール | `dc5lib/ensembles.py` | `dc5lib/union.py` |
| 使うスクリプト | `run_ensemble_eval.py`・`run_ensemble_diag.py`・`run_hazard_map.py` | `run_union_*.py`・`run_miss_overlap.py`・`run_stage2_room.py` |

**`postprocess.py` は旧側の `ensembles.yaml` に同居している**のに、
和集合の刈り取り（`union_with`）も定義する。**境目をまたぐのはここ。**

**新側の「混ぜてよいか」は `union.verify` が見る**が、2026-11-11 まで
**呼んでいるスクリプトが1本も無かった**（grep で確認）。いまは
`run_union_blind.py` と `run_stage2_eval.py` が推論の前に `verify_names` を呼ぶ。
`union6` の6本のうち**5本は素性の無い古い重み**（実測）なので、`verify` は
その分割を「分からない」としか言えない ── **確かめるのは `tools/audit_splits.py`**。
旧側の `ensembles.check()` が何を見ているかは**未読**（※）。

### 7.7 記録を書く場所は6つ

`results.record_eval` を呼ぶ場所（grep で数えた）。**歯止めが全部に届いているか**を見る。

| 書く場所 | 記録するもの | 推論の前に見るもの |
|---|---|---|
| `dc5lib/evaluate.py` の `_record` | 素のタイル（`通常`）| split・ずらした窓・枚数とラベル・学習した地域 |
| `analysis/run_overlap_eval.py` | 単体のオーバーラップ | 分割と集合の組み合わせ・学習した地域 |
| `analysis/run_overlap_prune.py` の `record`（`run_stage2_eval.py` も使う）| 刈り取り後 | 同上（2段目は構成員の全員＋`verify_names`）|
| `dc5lib/union.py` の `record`（`run_union_blind.py`）| 和集合そのもの | 同上（構成員の全員＋`verify_names`）|
| `analysis/run_ensemble_eval.py`（**旧**）| 確率平均 | **学習した地域も分割も見ない**（旧側は触らない）|
| `tools/import_existing_results.py` ※ | 古い CSV の取り込み | 未検査 |

### 7.8 `datasets["train"]` は素のタイルではない

`build_loaders` の返りの `datasets` は4つある。**`train` だけが違う。**

| 鍵 | 中身 |
|---|---|
| `train` | **オーバーラップ条件では乱数でずらした窓**（`max_shift > 0`）。学習用 |
| `val`・`test` | 素のタイル（`deterministic=True`）|
| `all` | 警戒区域ありの全件を素のタイルで（島根の補助 9,679枚）|

`eval_shimane.ipynb` のセル3は `train`・`val`・`test` をつないで測っていた。
本物の島根の pkl で確かめると、学習用は抜き取り 20枚のうち **18枚が素のタイルと違った**。
**評価の差分に `datasets["train"]` や `ConcatDataset` が出てきたら止まって読む。**
`evaluate(record=True)` は推論の前に止める。

### 7.9 2段目は「別の名前の重み」と「キャッシュ」を持つ

2段目（`run_stage2_train.py`・`run_stage2_eval.py`）は、1段目とは**別の成果物**を持つ。

| もの | 場所 | 何が鍵か |
|---|---|---|
| かたまりのデータ | `cache/stage2/<1段目>__hiroshima__<split>[__union_…][__agree].npz` | 1段目の名前・split・相方・合意数。**1段目の重みの中身は鍵に入らない** |
| 2段目の重み | `weights/<--name>/best_model.pth` | `--name` だけ。**既定の名前は実在する重み**（`Post_SAM_OL_Stage2` が指す）|
| 後処理の定義 | `ensembles.yaml` の `postprocess:` | `base`・`union_with`・`model`・`threshold` |

**読んで分かったこと（2026-11-12）**

- 2段目の学習データは **1段目の検証 split のかたまり**。それをタイル単位で 8:2 に割る
- **しきい値を選ぶ「検証 split」の8割は2段目の学習データ**（テストは汚れないが、検証の値は楽観的）
- 2段目の重みに書いてあるのは `stage1`・チャネルの構成・検証AUC。
  **相方と乱数の種は 2026-11-12 より前の重みには無い**（12本とも。実測）
- 2段目の3分割は `dc5lib/splits.resolve` と並びまで同じ（実測）
- 歯止め ── 既存の重みの上書き（`guard_existing_weights`）・`--split val --record`
  （`guard_record_split`）・1段目や相方の取り違え（`guard_stage2_weights`）

### 7.11 どの道が、どの入力の条件を測れるか
