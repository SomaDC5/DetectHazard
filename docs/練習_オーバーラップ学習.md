# 練習 — オーバーラップ学習をノートブックで回す

**ノートブックでできる。** 既存のセルの差し替え1か所と、追加1セルで済む。
学習ループ・モデル・損失・評価セルは一切触らない。

条件は `experiments/FinalFusion_SAM_APM_OverlapTrain/` に作成済み。
実装は `dc5lib/overlap.py`。考え方は `展望_再現率をどう上げるか.md` 5節。

---

## 0. 何をするのか

いま学習は**固定格子の切り方しか見ていない**。推論で窓をずらすと箇所F が
+0.047〜+0.060 上がる（`実験のまとめ.md` 2節）ので、学習時と推論時で
入力の切り方が食い違っている。そこで学習でもずらす。

中央タイルの周囲8枚を貼って 384×384 を作り、そこから 128×128 を
**最大 64px ずらした位置**で切り出す。実質はランダムクロップ拡張で、
データ拡張は学習側で唯一 0.672〜0.681 の帯を抜けた施策（面積F +0.0247）
なので方向が一致している。狙いは**再現率**。

**構造は出発点と同一**なので、出る差は切り方の差だけになる。

---

## 1. いちばん大事なこと — 分割をまたぐ漏れ

学習タイルの周囲を貼ると、窓は隣のタイルの半分まで入る。
**その隣が検証やテストのタイルだと、評価用の画素が学習に入る。**

この研究は一度テスト集合の汚染で結論が2つ覆っている（`実験のまとめ.md` 8節）。
同じことを繰り返さないため、貼ってよい近傍は

```python
allowed = allowed_except(len(dataset2.No), idx_val, idx_test)
```

という**「検証とテスト以外すべて」**の形で作る。この規則なら取り違えにくい。

> **背景タイルを含めてよい理由。** bg_ratio=0 の条件では、背景タイル
> （警戒区域を含まない 23,332 枚）は学習にもテストにも使われない。
> 文脈として貼っても誰のデータも漏れない。含めると使える近傍が
> **平均 3.28 → 5.64 枚**に増える（広島・実測）。
> bg_ratio>0 の条件では背景の一部がテストに入るが、
> それは `idx_test` に含まれるので自動的に除かれる。

貼れなかった近傍は中央タイルの鏡像で埋まる。これは**偽の地形**なので、
`OverlapDataset` は**使える近傍の方向にだけずらす**ようにしてある。
合成データでの確認では、方向を選ばない場合に 65.9% が鏡像を踏むのに対し、
方向を絞ると 0.0% になる。

## 2. 広島での実測（近傍がどれだけ使えるか）

学習 8,889 / 検証 2,963 / テスト 2,964（警戒ありタイルを 6:2:2）。

| 貼ってよい範囲 | 8近傍が揃う | 平均 | 近傍4枚以上 |
|---|---|---|---|
| 学習集合のみ | 0.2% | 3.28 / 8 | 44.0% |
| **学習 + 背景（既定）** | **8.7%** | **5.64 / 8** | **91.9%** |
| 学習 + 検証 + 背景 | 29.9% | 6.74 / 8 | 98.1% |

3行目は検証が漏れる。検証は最良エポックの選択に使うので、
**混ぜるとモデル選択が歪む。** 採らない。

## 3. ノートブックの変更点

### 3.1 追加するセル（分割セルの直後）

値ではなく**位置の添字**で分け直す。同じ `test_size` / `random_state` で
`np.arange` を分割すれば同じ分け方になる。そのことを `No` の一致で検算する。

```python
import numpy as np

idx_all = np.arange(len(dataset2.No))
idx_trainval, idx_test = train_test_split(idx_all, test_size=0.2, random_state=42)
idx_train, idx_val = train_test_split(idx_trainval, test_size=0.25, random_state=42)

assert [dataset2.No[i] for i in idx_train] == list(No_train), "学習の分割がずれている"
assert [dataset2.No[i] for i in idx_val] == list(No_val), "検証の分割がずれている"
assert [dataset2.No[i] for i in idx_test] == list(No_test), "テストの分割がずれている"
```

**この assert が通らないまま進めないこと。** 添字がずれていると、
別のタイルを近傍として貼ることになる。

### 3.2 差し替えるセル（train_dataset を作っているところ）

```python
from dc5lib.overlap import OverlapDataset, allowed_except

# 文脈には dataset3（背景）も使う。添字は dataset2 を先、dataset3 を後に並べた通し番号
ctx_dem  = list(dataset2.DEM)      + list(dataset3.DEM)
ctx_air  = list(dataset2.AirPhoto) + list(dataset3.AirPhoto)
ctx_mask = list(dataset2.Mask)     + list(dataset3.Mask)
ctx_geo  = list(dataset2.GeoInfo)  + list(dataset3.GeoInfo)

allowed = allowed_except(len(ctx_geo), idx_val, idx_test)

train_dataset = OverlapDataset(
    ctx_dem, ctx_air, ctx_mask, ctx_geo,
    indices=idx_train, allowed=allowed,
    max_shift=64,          # 0 にすると従来と同じになる
    transform=None, seed=42,
)
print("8近傍が揃うタイル {:.1f}%  平均 {:.2f}/8".format(*train_dataset.coverage()))
```

> **`dataset2` だけを渡さないこと。** `dataset2` は警戒ありの 14,816 枚だけで、
> 背景 23,332 枚は `dataset3` に分かれている。`dataset2` だけだと
> **8近傍が揃うのが 0.2%（平均 3.28/8）**まで落ちる。
> 両方渡すと 8.7%（平均 5.64/8）になる。
>
> `dataset2` はテンソル (1,H,W)、`dataset3` は素の配列 (H,W) / (H,W,3) と
> 形が違うが、`OverlapDataset` が内部で揃えるのでそのまま渡してよい。

**検証とテストは `DualInputDataset` のまま**にする。
評価の切り方を変えると他の条件と比べられなくなる。

返すものは `((dem, air), mask)` で `DualInputDataset` と同じなので、
`DataLoader` 以降は何も変えなくてよい。

## 4. 確認したこと

`dc5lib/overlap.py` は合成データで次を確認してある。

実際に適用されるずらし幅（広島・学習8,889枚で実測）。

| | 値 |
|---|---|
| 平均ずらし幅 | 25.8px（縦）/ 25.9px（横） |
| まったくずれない割合 | **1.6%** |
| 窓に占める中央タイル | 63.5%（残り 36.5% が本物の近傍） |

**8近傍が揃うのが 8.7% でも、使える方向にだけずらすので実害は小さい。**

| 確認 | 結果 |
|---|---|
| 貼り合わせの向き（緯度は上が大きい） | 中央が自分、上が北で一致 |
| allowed 外の画素が入らないか | 1,000回以上切り出して 0件 |
| 返す形・型・正規化 | (1,128,128)/(3,128,128)、航空写真 0–1 |
| `deterministic=True` が元タイルと一致するか | 完全一致 |
| 鏡像を踏む割合 | 方向を選ばない 65.9% → 絞ると 0.0% |
| ノートブックの流れ（分割→Dataset→DataLoader→model） | 通る |

**まだ確認していないこと: 実データでの学習。** 効くかどうかは未測定。

## 6. 調整できるところ

| 引数 | 既定 | 変えるとどうなるか |
|---|---|---|
| `max_shift` | 64 | 小さくすると中央タイルの割合が増える。0 で従来と同じ |
| `allowed` | 検証・テスト以外 | 狭めると鏡像が増える。広げると漏れる |
| `transform` | None | 既存の `JointTransform` を渡せば、ずらしたあとに掛かる |

`max_shift=64` は推論のオーバーラップ（9窓・64px刻み）に合わせた値。
推論と学習で同じ幅にしておくと、効果の切り分けがしやすい。
