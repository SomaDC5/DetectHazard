## 2. 重大 ── 黙って違うものを測る・検査が効いていない

### 2.1 `templates/eval_shimane.ipynb` のセル3が、ずらした窓で測っていた

- セル3は補助の 9,679枚を `ConcatDataset([ld.datasets[k] for k in ("train", "val", "test")])` で作る
- `build_loaders` の `datasets["train"]` は `deterministic=False`・`max_shift=config の値`
- オーバーラップ条件（`max_shift=64`）では `OverlapDataset.__getitem__` が**乱数でずらした窓**を返す（M8）

**起きること** ── 9,679枚のうち学習の 5,807枚が素のタイルでなくなる。値は測るたびに変わり、
表示は「素のタイル」のまま。**オーバーラップ無しの条件では起きない**ので気づきにくい。
セル3は 2026-11-10 に `record=True` になったので、回せば「島根・警戒のみ」に記録される。

**記録には入っていない**（`evaluate()` が書いた行は広島 2,964枚の4行だけ。島根・警戒のみの
17行は 2026-09〜10 の面積評価）。

**直した** ──
- `dc5lib/pipeline.py`：`datasets["all"]` を足した（警戒区域ありの全件・`deterministic=True`）
- `templates/eval_shimane.ipynb`：セル3は `ld.datasets["all"]` を測る
- `dc5lib/evaluate.py`：`_guard_record` が、ずらした窓のデータセットを**推論の前に**止める。
  `record=False` でも注意を出す

### 2.2 `analysis/` の道は条件の分割を見ない

- 広島の対象タイルは `run_overlap_eval.target_tiles` → `analysis/data.hiroshima_test_indices`
  で決まり、**どの条件でも random/42 のテスト**になる
- 2026-11-08 に `FinalFusion_SAM_APM_BlockSplit` の config へ `split:` を宣言したが、
  **こちらの道は config の `split:` を読まない**ので、宣言しても変わらない

**起きること** ── `run_overlap_eval.py --region hiroshima --conditions FinalFusion_SAM_APM_BlockSplit --record`
が、テスト 2,964枚のうち 2,158枚が学習か検証のタイルである値を
「広島・警戒のみ・オーバーラップ」として記録する（M5）。素のタイルの集計
（`run_inference.py`・`run_instance_eval.py`）は**既定で全条件を回す**ので、
指定しなくても同じ値をキャッシュに書く。

**記録には入っていない**（M6）。

**直した** ──
