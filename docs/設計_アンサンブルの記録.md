# 設計：アンサンブル（和集合）の実験を記録に残す

**実装の前に書いた設計書。** 何が記録されていないかを**コードで確かめてから**
決めた。推測で足していない。

関係する手順書は `docs/アンサンブルの使い方.md`、
数字の出どころは `docs/展望_再現率をどう上げるか.md` の `42`〜`45`。

---

## 1. いま記録されているもの・いないもの（実測）

| 測るもの | 出す道具 | `results/evals/` に入るか |
|---|---|---|
| 単体条件の素のタイル | `tools/run_eval.py` | **入る**（2026-10-30 に足した）|
| 単体条件のオーバーラップ推論 | `analysis/run_overlap_eval.py --record` | **入る** |
| 刈り取り後（後処理） | `analysis/run_stage2_eval.py --record` | **入る**（`--postprocess` の定義が要る）|
| **和集合そのもの**（刈り取り前の箇所R/P/F）| `analysis/run_union_blind.py` | **入らない** |
| **床・天井** | `run_union_blind.py` / `run_union_subsets.py` | **入らない**（CSV のみ）|
| **構成員が誰か** | `unions/*.yaml` | 記録の `note` に**入らない** |
| **シードごとの値** | — | **入らない**（後述の2が原因）|

## 2. 確かめた穴（コードの行つき）

### 2.1 同じ後処理名でシードを分けて記録できない

`dc5lib/results.py` の `record_eval` は、古い記録を**この鍵で消す**。

```python
key = (condition, region, tileset, scope, metric_kind, setting)
```

`analysis/run_overlap_prune.py` の `record()` は `condition=pp.name` を渡す。
`pp.model`（2段目の重みの名前）は鍵に入らない。

> つまり **`Post_Union6_Stage2` のまま s1・s2・s3 を記録すると、
> 後のものが前のものを消す。** 3シードは残らない。

`build_metrics_csv` の安全網も同じ鍵なので、JSON が残っても
`metrics.csv` には1行しか出ない（`dc5lib/results.py:208`）。

### 2.2 追加の列は `metrics.csv` に出ない

`record_eval(**fields)` は余った項目を JSON に入れるが、

```python
w = csv.DictWriter(f, fieldnames=COLUMNS, extrasaction="ignore", ...)
```

`COLUMNS` に無い項目は**捨てられる**（`dc5lib/results.py:224`）。
だから `union_with` や `stage2_model` をただ渡しても表に出ない。

### 2.3 構成員が記録に残らない

`record()` の `note` は `pp.display()` を使い、`display()` は
`label or f"{base} + 刈り取り(...)"`（`dc5lib/postprocess.py:82`）。
`union_with` は**散文のラベルにしか現れない。**
`Post_Union_SAM_DEM_Stage2` のラベルは「SAM+APM と DEM+APM の和集合」で、
**機械では構成員を取り出せない。**

### 2.4 しきい値をどの split で選んだかが残らない

`drop_quantile` は分位の記録用で、「検証split で選んだ」という事実は
`note` の散文にしかない。

### 2.5 和集合そのもの（刈り取り前）が記録されない

`44.9` の 箇所R 0.8958／0.7575、上限 箇所F 0.9450／0.8620、
床 465／3,204 は**どれも `metrics.csv` に無い。** CSV とこの docs にしかない。

## 3. 決めたこと

### 3.1 シードは**後処理の定義を分ける**（コードを変えない）

`ensembles.yaml` の `postprocess:` に**1シード1定義**を置く。

```yaml
  Post_Union6_Stage2_s1:
    base: FinalFusion_SAM_APM_OverlapTrain
    union_with: [ …5本… ]
    model: Stage2_Union6_s1
    threshold: 0.40
```

**なぜ定義を分けるか。** `condition` が別名になるので `2.1` の上書きが起きない。
`record_eval` の鍵を変えるほうが筋が良さそうに見えるが、**鍵を変えると
過去841件の記録の同一性が変わる**ので触らない。

> **既存の `Post_Union_SAM_DEM_Stage2` などは改名しない。** 記録済みの
> `condition` 名を変えると `metrics.csv` の履歴が切れる。新しいものだけ
> `_s<N>` を付ける。

### 3.2 `COLUMNS` に4列足す

| 足す列 | 中身 | なぜ |
|---|---|---|
| `members` | 構成員の条件名を `|` で連ねたもの | `2.3`。**誰を混ぜたかが表から分かる** |
| `n_members` | 構成員の本数 | 「3本対6本」を表で絞れる |
| `stage2_model` | 2段目の重みの名前 | `2.1`。シードが判別できる |
| `thr`・`thr_split` | しきい値と、**それを選んだ split** | `2.4`。テストで選んでいないことが表に残る |

**既存の841件には空で入る。** `DictWriter` は無い項目を空欄にするので
古い記録は壊れない（`extrasaction="ignore"` は余りを捨てるだけ）。

### 3.3 `record()` に素性を渡させる

`analysis/run_overlap_prune.py` の `record(pp, region, res)` に
省略可能な引数を足し、`run_stage2_eval.py` から渡す。
**`pp` から取れるものは `pp` から取る**（`union_list()`・`model`・`threshold`）。
呼ぶ側が重複して持たない。

### 3.4 和集合そのものも記録する

`run_union_blind.py` に `--record` を足す。記録するのは

| `condition` | `scope` | 中身 |
|---|---|---|
| `Union_<名前>`（例 `Union_union6`）| `和集合` | 刈り取り前の箇所R/P/F |
| 同上 | `和集合上限` | `2R/(1+R)`（完璧な刈り取りの上限）|

**床と天井は箇所R/P/F の形をしていない**ので、
`recall=天井 / precision=床 / f1=天井` のように**無理に入れない。**
`note` に件数と割合を書き、**出どころの CSV 名を必ず書く**。
床を表で扱いたくなったら、そのとき別の表を設計する
（いま無理に入れると `recall` 列の意味が壊れる）。

### 3.5 やらないこと

- **`record_eval` の鍵を変えない**（`3.1`）
- **既存の `condition` 名を改名しない**（`3.1`）
- **床・天井を `recall`/`precision` 列に入れない**（`3.4`）
- **`ensembles.yaml` を `postprocess` ごとに分割しない。** 旧側の
  アンサンブル定義と同居しているのは紛らわしいが、
  **記録済みの定義を動かす危険のほうが大きい**（`docs/アンサンブルの使い方.md` の `0`）

## 4. 実装の順番

1. `dc5lib/results.py` の `COLUMNS` に4列（`3.2`）
2. `analysis/run_overlap_prune.py` の `record()` に素性（`3.3`）
3. `analysis/run_stage2_eval.py` から渡す
4. `ensembles.yaml` に `Post_Union6_Stage2_s1/_s2/_s3` と
   `Post_Union3_Stage2_s1/_s2/_s3`（**基準も同じ形で記録する**）
5. `run_union_blind.py` に `--record`（`3.4`）
6. `tools/check.py` が通ることを確かめ、**測り直して記録する**
7. `docs/アンサンブルの使い方.md` に記録の節を足す
