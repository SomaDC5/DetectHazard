# 練習：新しい条件を自分の手で作る

手順を体で覚えるための手引き。**各ステップに「確認」を入れてある**ので、
一つずつ通しながら進めること。詰まったら確認コマンドの出力を見れば、
どこまで出来ていてどこが違うかが分かる。

例として **`UNet_SAM_3split`**（`UNet_SAM_InstLoss` から損失だけ従来に戻した
対照条件）を作る。名前とパラメータを変えれば他の条件でも同じ。

> **なぜこの条件か**
> `UNet_SAM_InstLoss` を学習しても、比べる相手が
> `Train_Hiroshima_Test_Shimane_OnlySAM`（検証分割なしの旧プロトコル）しか無い。
> それだと「箇所正規化損失が効いたのか、3分割にしたから変わったのか」が
> 切り分けられない。損失以外を全部揃えた対照条件が要る。

## 1. 名前を決める（コードを書く前に）

ぶつかるのは名前。**学習コードを書く前**に確かめる。

```bash
./.venv/bin/python tools/new_experiment.py --list
```

ローカルと、相手のPCが使っているリモートブランチの両方が出る。
この一覧に無い名前を選ぶ。

**やってみる**：わざと既存の名前を入れると、どう止まるか見ておく。

```bash
./.venv/bin/python tools/new_experiment.py UNet_SAM_InstLoss --no-fetch
# → 「ローカルに同名の条件があります」で止まる
```

---

## 2. 雛形を作る

`UNet_SAM_InstLoss` をひな形にして、**損失だけ**従来に戻す。

```bash
./.venv/bin/python tools/new_experiment.py UNet_SAM_3split \
    --from UNet_SAM_InstLoss \
    --loss focal_tversky --beta 0.3 \
    --note "UNet_SAM_InstLoss の対照条件。損失は従来の focal_tversky、3分割は同じ"
```

`--beta 0.3` を明示しているのは、`UNet_SAM_InstLoss` が `beta: 0.5`
（箇所重みで見逃し側が強まるぶん上げてある）を引き継いでしまうため。
対照条件は従来値に戻す。

**確認**

```bash
cat experiments/UNet_SAM_3split/config.yaml
./.venv/bin/python -m dc5lib.losses UNet_SAM_3split
```

期待する出力。

```
UNet_SAM_3split    focal_tversky(alpha=0.7, beta=0.3, gamma=0.75)
```

`※重みマップが必要` が付いていなければ正しい。付いていたら `--loss` の指定が
効いていないので、`config.yaml` の `train.loss.type` を直接直す。

---

## 3. config.yaml を読んで理解する

自動生成されたものを一度自分で読むこと。ここが条件の定義そのもの。

| 項目 | 意味 | 変えると |
|---|---|---|
| `name` | **フォルダ名と一致必須** | ずれると `check.py` が落ちる |
| `arch` | `dc5lib/models.py` のクラス名 | 未登録だと `check.py` が落ちる |
| `family` | 図表のグループ分け | 結果の並びが変わるだけ |
| `inputs` | 入力の構成。数・チャネル数 | モデル側の対応も要る |
| `augment` | データ拡張の有無 | ノートブックが `JointTransform` を使うか |
| `bg_ratio` | 学習に混ぜる背景タイルの割合 | いまは全条件 0.0 |
| `dataset` | 地域ごとの pkl | `regions.yaml` の `dir` がキー |
| `train.loss` | **損失。ノートブックはここを読む** | 損失が切り替わる |

---

## 4. ノートブックを確認する

雛形と一緒にノートブックも複製され、2箇所が自動で書き換わっている。

```bash
./.venv/bin/python - <<'EOF'
import json
nb=json.load(open('experiments/UNet_SAM_3split/unet_new_data_ver3_72_shimane_eval.ipynb',encoding='utf-8'))
for i,c in enumerate(nb['cells']):
    for ln in ''.join(c['source']).split('\n'):
        if 'CONDITION =' in ln or 'build_loss' in ln:
            print(f'c{i}: {ln.strip()}')
EOF
```

期待する出力。

```
c0: from dc5lib.losses import build_loss, describe, weight_params
c0: CONDITION = "UNet_SAM_3split"
c7: _, NEEDS_WEIGHT = build_loss(CONDITION)
c10: criterion, NEEDS_WEIGHT = build_loss(CONDITION)
```

**`CONDITION` が新しい名前になっていること**を必ず確認する。ここが古いままだと、
ひな形の重みを上書きしてしまう。

この条件は `NEEDS_WEIGHT == False` になるので、
`UNet_SAM_InstLoss` で入れた重みマップの配線は**そのまま素通りする**。
ノートブックを手で削る必要はない。実際に走らせて確認してある。

| | `UNet_SAM_InstLoss` | `UNet_SAM_3split` |
|---|---|---|
| `NEEDS_WEIGHT` | True | False |
| `W_ALL` | 箇所ごとの重み | 全部 1.0 |
| `ImageDataset` が返す数 | 3（image, mask, weight） | 2（image, mask） |
| `train のバッチ` の出力 | `3 個` | `2 個` |

セル9の出力が `train のバッチ: 2 個` になっていれば、素通りできている。

## 8. 記録して共有する

```bash
./.venv/bin/python -m dc5lib.sync verify     # 増えた重みを在庫表に反映
./.venv/bin/python tools/check.py
git pull
git add -A
git commit -m "UNet_SAM_3split を学習・評価"
git push
```

`sync verify` を忘れると、重みが在庫表に載らず、SSDを揃えるときに取りこぼす。
忘れても `sync` 側が止めてくれるが、癖にしておくとよい。

## つまずきやすいところ

| 症状 | 原因と対処 |
|---|---|
| `dc5lib が見つかりません` | リポジトリの外で jupyter を起動した。`cd` してから |
| `dc5-data が見つかりません` | SSDが挿さっていない |
| `dc5-data が複数見つかりました` | SSDを2台挿している。`DC5_SSD_ID=A` |
| 重みが別条件の場所に保存される | セル0の `CONDITION` が古いまま |
| `check.py` が name の不一致で落ちる | フォルダ名を変えたのに `config.yaml` を直していない |
| `check.py` が metrics.csv で落ちる | `python tools/make_metrics.py` で作り直す |
| 損失が切り替わらない | `config.yaml` の `train.loss.type` を確認。`python -m dc5lib.losses <条件名>` |
| Mac で異常に遅い | `python -m dc5lib.device` が `mps` を返すか確認 |

---

## まとめ：毎回やること

```
1. git pull                                     相手の変更を取り込む
2. new_experiment.py --list                     名前を決める
3. new_experiment.py <名前> --from <ひな形> ...  雛形を作る
4. config.yaml を読む                            自分が何を変えたか確認
5. check.py → commit → push                     名前を予約
6. ノートブックで学習                             CONDITION を必ず確認
7. analysis/run_*.py → make_metrics.py           評価
8. sync verify → commit → push                   記録して共有
```

慣れたら 3 を飛ばして手でフォルダを作ってもよいが、
`new_experiment.py` は「他のPCのブランチとの名前衝突」と
「大文字小文字だけ違う名前」も見てくれるので、使ったほうが安全。
