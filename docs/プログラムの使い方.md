## 0. 全体の流れ

```
定義                      道具                               出るもの
----------------------    -------------------------------    ---------------------------
experiments/<条件>/       tools/new_experiment.py            config.yaml・ノートブック
  config.yaml
        │
        ▼
                          tools/run_training.py              重み（SSD）・曲線・広島の記録
        │
        ▼
                          tools/run_eval.py                  素のタイルの記録（広島）
                          analysis/run_overlap_eval.py       オーバーラップ推論の記録
        │
        ▼
ensembles.yaml の         analysis/run_overlap_prune.py      ロジット刈り取り
  postprocess:            analysis/run_stage2_train.py       2段目の重み
                          analysis/run_stage2_eval.py        2段目で刈った記録
        │
        ▼
unions/*.yaml             analysis/run_union_blind.py        和集合・床・上限
                          analysis/run_union_subsets.py
        │
        ▼
                          tools/check.py ほか                出す前の検査
```

置き場所は3つ。

| 場所 | 中身 | 揃える手段 |
|---|---|---|
| リポジトリ | コード・`config.yaml`・`results/`（記録と曲線）| git |
| SSD の `dc5-data/` | `weights/`・`checkpoints/`・`datasets/`（pkl）・`cache/` | `python -m dc5lib.sync` |
| SSD の `dc5-data/cache/analysis/` | 解析の表（`tiles`・`instances`・`coverage`・`triage`・`building` など）| 同上 |

## 3. 条件を作る

```bash
python tools/new_experiment.py <条件名> --note "何を試すか"
```

- **`--from` は付けない。** 付けると既存のノートブックを複製する（警告が出る）。
  付けなければ `templates/train.ipynb` と `templates/eval_shimane.ipynb` から作られる
- 名前の衝突（ほかのブランチで作業中のものを含む）を見てから作る。
  オフラインなら `--no-fetch`
- 出来るのは `experiments/<条件名>/` の `config.yaml`・`train.ipynb`・`eval_shimane.ipynb` の3つ
- **学習の前に `config.yaml` だけ push して名前を予約する**（2台で並行して学習するため）

よく使う引数。

| 引数 | 意味 |
|---|---|
| `--arch` | モデルクラス名（`dc5lib/models.py` に登録されているもの）|
| `--inputs` | 入力の構成。例 `SAM+APM`・`SAM+APM+GEO` |
| `--family` | 図表のグループ分け |
| `--loss`・`--alpha`・`--beta`・`--gamma` | 損失 |
| `--epochs`・`--seed` | 学習設定 |

`config.yaml` に書く項目は実装書 `2`。**値はすべて `config.yaml` に書く**
（ノートブックに書かない）。作ったら次を確かめる。

```bash
python -m dc5lib.traincfg <条件名>       # 設定が読めているか
python tools/vram_probe.py <条件名>      # 学習1ステップが GPU に載るか
```

> **学習し終えたら `config.yaml` に `protocol: v3-base` と `seeded: true` を書く。**
> 作ったばかりの config には `protocol` が無く、既定の `v1-notebook` になる。

## 4. 学習する

**長い学習は `tools/run_training.py` で回す**（ノートブックの実行はカーネルが
何も出力せずに消えることがある）。

```bash
python tools/run_training.py <条件名> --epochs 1 --dry    # 試運転（本物を上書きしない）
python tools/run_training.py <条件名>                      # 本番
```

| 引数 | 意味 |
|---|---|
| `--dry` | 重みと曲線を `cache/dry/` に書く |
| `--epochs N` | config の `epochs` を上書きする（試運転用）|
| `--no-eval` | 学習のあとの評価を省く |
| `--no-expect` | 分割の期待値の照合を飛ばす（csv 分割の条件など）|
| `--overwrite` | 既存の重みと曲線を作り直す（**既定は止まる**）|
| `--region` | 既定は `Hiroshima` |

学習を始める前に止まるもの（**pkl を読む前に止まる**）。

| 止まる条件 | 対処 |
|---|---|
| 重みか曲線が既にある | 作り直すなら `--overwrite`。**既存の重みは作り直さないのが原則** |
| config に `augment: true`・`train.init_from` がある | `fit` には届かない設定。実装書 `3.3` |
| `aux_lambda` > 0 の条件 | `fit` は補助損失を掛けない。`hooks` が要る（実装書 `3.4`）|
| 分割の枚数・指紋が期待値と違う | pkl か分割の指定が違う。**回さない** |

終わると広島のテスト 2,964枚で測り、記録できる条件なら `results/evals/` に入る
（記録できるかは学習の前に表示される）。

### 4.1 ノートブックで回すとき

`experiments/<条件名>/train.ipynb` を上から回す。中身は `dc5lib` を呼ぶだけで、
`run_training.py` と同じ関数を同じ順に呼ぶ。**cell 4 の検算を見てから先に進む。**

| 見るところ | 広島で合うべき値 |
|---|---|
| 警戒区域あり | 14,816 |
| 学習 / 検証 / テスト | 8,889 / 2,963 / 2,964 |
| 並びの指紋 / 分割の指紋 | `a75ad23bad3e` / `653b8cbe3d28` |

そのあと `eval_shimane.ipynb`（島根の補助 9,679枚）。

### 4.2 学習をやり直すとき

```bash
python tools/reset_condition.py <条件名>            # 何が消えるかを見るだけ

## 5. 測る（1本の条件）

| 何を測るか | コマンド | 記録 |
|---|---|---|
| 素のタイル（広島テスト 2,964枚）| `python tools/run_eval.py <条件名…>` | される（`--no-record` で見るだけ）|
| 素のタイル（島根）| `python tools/run_eval.py <条件名> --region Shimane --no-record` | **できない**（測るのはテスト 1,936枚で、その枚数にラベルが無い）|
| オーバーラップ推論（広島 2,964枚・島根 24,569枚）| `python analysis/run_overlap_eval.py --region both --conditions <条件名…> --record` | `--record` を付けたときだけ |
| ロジット刈り取り | `python analysis/run_overlap_prune.py --condition <条件名>` | `--postprocess <名前> --record` のとき |

- **`run_eval.py --split val`／`train` は `--no-record` と一緒でないと止まる**
  （記録の鍵に split が入らないので、テストの行を置き換えてしまう）
- `run_overlap_eval.py` は別の分割で学習した条件（ブロック分割など）を入口で止める
- 島根の主系統は**全 24,569枚**（`subset: all`）で、記録できる経路は `run_overlap_eval.py` である

刈り取りのしきい値は**別のタイルで選んで残りで測る**。
地域をまたぐときは広島で決めた値をそのまま当てる。

```bash
python analysis/run_overlap_prune.py --condition <条件名> --region shimane --thr <広島の値>
python analysis/run_overlap_prune.py --postprocess Post_SAM_OL_Logit30 --record
```

## 6. 2段目（刈り取りを学習する）

```bash
# 1) かたまりデータを作る（1段目の推論。SSD にキャッシュする）
python analysis/run_stage2_train.py --stage1 <1段目> --build --union-with <相方…> [--agree]

# 2) 学習する。**新しい名前を付ける**
python analysis/run_stage2_train.py --stage1 <1段目> --train --name <新しい名前> \
    --union-with <相方…> [--agree] --seed 1

# 3) 検証 split でしきい値を掃く
python analysis/run_stage2_eval.py --stage1 <1段目> --model <名前> --union-with <相方…> --split val

# 4) テストで測る（3 のしきい値を渡す）
python analysis/run_stage2_eval.py --stage1 <1段目> --model <名前> --union-with <相方…> \
    --split test --thr <3 の値>
```

| 決まり | 守らないとどうなるか |
|---|---|
| **`--train` には新しい `--name` を付ける** | 既定の `Stage2_SAM_OL_v1` は実在する重みで、付け忘れると**学習の前に止まる**（`--overwrite` で上書き。記録した数字が出なくなるので普通は使わない）|
| `--build` と `--train` で `--union-with`・`--agree` を揃える | キャッシュの名前が変わり「先に --build を」で止まる |
| `--agree` は `--union-with` と一緒に使う | 止まる |
| **`--union-with` に渡すのは基準を含まない並び**（基準は `--stage1`）| `8.3` |
| しきい値は `--split val` で選ぶ。**テストで選ばない** | |
| **2段目を学習し直したら、しきい値も選び直す** | 最良点に至るしきい値は 0.35〜0.50 で動く（`再現手順.md` の `4`）|
| `--record` は `--split test` のときだけ | `--split val --record` は推論の前に止まる |
| `--record` には `--postprocess` が要る | 止まる。定義は `7` |
| 1段目に建物などの3入力目を持つ条件は置けない | 止まる。相方（`--union-with`）としてなら使える |

**帯を測るときは初期化のシードだけ振る**（`--seed 1`・`2`・`3`、`--split-seed` は 42 のまま）。
名前はシードごとに分ける（`…_s1`・`…_s2`・`…_s3`）。

診断用のフラグ（`--wide`・`--landuse`・`--no-scalar`・`--no-narrow`・`--no-logit`・
`--jitter`・`--augment`）は `python analysis/run_stage2_train.py --help`。

## 7. 後処理を定義して記録する

後処理（1段目＋和集合＋刈り取りの組み合わせ）は `ensembles.yaml` の `postprocess:` に書く。

```yaml
  Post_Union6Agree_Stage2_s2:
    label: 6本の和集合 + 合意数チャネル + OL推論 + 2段目CNN（seed 2）
    base: FinalFusion_SAM_APM_OverlapTrain     # 1段目
    union_with:                                # 相方（基準を含まない）
      - FinalFusion_DEM_APM_OverlapTrain
      # …
    inference: オーバーラップ
    feature: stage2                            # logit_max なら学習なしの刈り取り
    model: Stage2_Union6Agree_s2               # 2段目の重みの名前
    threshold: 0.50                            # 絶対値で持つ
```

```bash
python -m dc5lib.postprocess                 # 定義の一覧
python analysis/run_stage2_eval.py --postprocess Post_Union6Agree_Stage2_s1 \
    --split test --region hiroshima --record --thr-split "広島の検証split"
```

- **`--union-with` は省く。** 定義のものが使われる。指定して食い違えば推論の前に止まる
- **シードごとに定義を分ける。** 記録の鍵に2段目の重み名が入らないので、
  同じ名前で複数シードを記録すると後のものが前を消す
- `--thr-split` に書いた文字列が記録に残る（しきい値をどの split で選んだか）
- 島根は `--region shimane`。**しきい値は広島で選んだ値をそのまま当てる**

## 8. アンサンブル

### 8.1 2系統ある。どちらの話かを先に確かめる

| | 旧：確率を混ぜる | 新：和集合をとる |
|---|---|---|
| 定義 | `ensembles.yaml` の `ensembles:` | `unions/*.yaml`（1件1ファイル）|
| モジュール | `dc5lib/ensembles.py`（複数形）| `dc5lib/union.py`（単数形）|
| 一覧 | `python -m dc5lib.ensembles` | `python -m dc5lib.union` |
| 測る | `analysis/run_ensemble_eval.py` | `analysis/run_union_blind.py` |
| 狙い | 箇所F・面積F を上げる（適合率を買う）| **床を下げる**（再現率の天井を上げる）|

古い手順書やコミットに `ensembles/`（フォルダ）とあれば、それは `unions/` のことである。

### 8.2 新側：いまある定義

| 名前 | 本数 | 中身 | `recorded:` |
|---|---:|---|---|
| `union3` | 3 | SAM+APM・DEM+APM・土地利用つき | あり |
| `union4` | 4 | + 建物（実＋仮想）| あり |
| `union5` | 5 | + 建物（実だけ）| あり |
| `union6` | 6 | + 建物（実だけ）の種ちがい | あり |
| `greedy4` | 4 | `run_miss_overlap.py` の既定 | なし |

**`recorded:` が付いた定義は動かさない。** 変えたいときは新しい yaml を作る。

### 8.3 `.all` と `members` ── 渡す先で要るものが違う

| 渡す先 | 要るもの |
|---|---|
| `run_union_blind.py --members` | **基準を先頭にした全員**（`.all`。`union6` なら6本）|
| `run_stage2_*.py --union-with` | **基準を含まない並び**（`members`。`union6` なら5本）|

名前を手で並べない。yaml から出す。

```bash
python -c "import sys;sys.path.insert(0,'.');from dc5lib import union;print(' '.join(union.get('union6').all))"
python -c "import sys;sys.path.insert(0,'.');from dc5lib import union;print(' '.join(union.get('union6').members))"
```

> `アンサンブルの使い方.md` の `3` にある同じ目的の1行は `ensemble.get(...)` と書いてあり、
> そのままでは `NameError` になった（改名の直し漏れ）。**2026-11-12 にあちらも `union.get(...)` に直した。**

### 8.4 新側：動かす順

**① 定義を見て、混ぜてよいかを確かめる**

```bash
python -m dc5lib.union union6
python tools/audit_splits.py --region both
```

`dc5lib.union` の検査は、構成員の不在・重みなし・`ensemble: false` の混入・分割の食い違いで止める。
ただし**素性の無い古い重みの分割は「分からない」としか言えない**（`union6` は6本のうち5本がそれ）。
**分割を確かめられるのは `audit_splits.py` だけ**である。既定で `unions/*.yaml` の全構成員を見る
（pkl を読むので広島＋島根で5分ほど）。**1組でも食い違ったら混ぜない。**

**② 和集合そのものを測る**

```bash
python analysis/run_union_blind.py --region hiroshima --members <.all の並び> --save --tag union6
python analysis/run_union_blind.py --region shimane  --members <.all の並び> --save --tag union6
```

| 引数 | 意味 |
|---|---|
| `--members` | 先頭が基準。省略すると `union3` の3本 |
| `--save` | `cache/analysis/coverage/union_blind__<地域>__<印>.csv` に保存する |
| `--tag` | 保存名の印。**構成員が `union5` の5本と違うときは必須** |
| `--record` | 和集合そのものを記録する。**`--name <unions の名前>` と `--save` が要る** |
| `--region` | `hiroshima` か `shimane`。`both` は無い |

構成員の本数ぶん、広島 2,964枚（島根は 24,569枚）を推論する。
`アンサンブルの使い方.md` の `4` は「6本なら1時間以上」としている。

推論の前に止まるもの。

| 止まる条件 | |
|---|---|
| 無印の CSV に、`union5` と違う構成員で保存しようとした | `--tag` を付ける |
| 同じ印の CSV が、別の構成員で既にある | `--tag` を変える（同じ構成員の測り直しは通る）|
| `--record` に `--name` か `--save` が無い | |
| `--name` の定義と `--members` が違う | `members` を渡すと基準が1本抜ける（`8.3`）|
| `ensemble: false` の条件・分割の食い違い | 混ぜられない |

**③ 部分集合の床を出す（推論しない）**

```bash

    --base SAM_APM DEM_APM SAM_APM_LU --candidates SAM_APM_BVB SAM_APM_BLD SAM_APM_BLD_seed2
```

名前は**略称**（`FinalFusion_` と `_OverlapTrain` を取ったもの。CSV の列名と同じ）。
`--base`・`--candidates` を省くと `union3` と `union5` から決まる。

**④ 構成員を1本だけ足す（全員を推論し直さない）**

```bash

```

記録済みの1本を推論し直して行の並びを照合し、合わなければ止まる。
**足せるのは構成員ごとの列（`cov_<略称>`・`lg_<略称>`）だけ。**
継ぎ足した表の `cov_union` と `n_light` は**もとの構成員のまま**なので読まない。
和集合の箇所R/P/F が要るなら②を全構成員で回す。

**⑤ 刈り取りまで通す** ── `6` と `7`。`--union-with` に `members` を渡す。

**⑥ 新しい定義を作る**

  - FinalFusion_DEM_APM_OverlapTrain

`python tools/check.py` を通す。
