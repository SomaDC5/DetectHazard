# アンサンブルの使い方

**手で動かすための手順書。** 本研究はアンサンブルを多用するので、
認識のずれが起きないように**動かす順番と、出た数字の読み方**をここに集める。

設計の理由は `docs/設計図_修正案.md` の `7.2`、
ノートブック側の契約は `docs/ノートブックの作り方.md` の `5`。

---

## 0. まず — **アンサンブルは2系統ある。どちらの話かを必ず確かめる**

先に新しい側（和集合）を作ったときに、名前が旧側とぶつかった。
**2026-10-30 に新側を改名した** ── `ensembles/` → **`unions/`**、`dc5lib/ensemble.py` → **`dc5lib/union.py`**。
名前がぶつかっていたのを解消したもので、**中身は変わっていない。**古い手順書やコミットに
`ensembles/` と書いてあったら `unions/` のことである。

| | 旧：**確率を混ぜる** | 新：**和集合をとる** |
|---|---|---|
| 何をする | 構成員の**予測確率を平均**して1枚の予測にする | 構成員の**二値マスクの論理和**をとる |
| 定義の場所 | **`ensembles.yaml`**（リポジトリ直下の1ファイル）| **`unions/*.yaml`**（フォルダ。1件1ファイル）|
| モジュール | `dc5lib/ensembles.py`（**複数形**）| `dc5lib/union.py`（**単数形**）|
| 一覧コマンド | `python -m dc5lib.ensembles` | `python -m dc5lib.union` |
| 主な測定 | `analysis/run_ensemble_eval.py` | `analysis/run_union_blind.py` |
| 狙い | **箇所F を上げる** | **床を下げる**（天井を上げる）|
| 説明文書 | `docs/練習_新しいアンサンブルを作る.md` | **この文書** |

> **どちらを使うのか迷ったら。** 「精度を上げたい」なら旧（確率平均）、
> 「**どの条件も拾えていない正解を減らしたい**」なら新（和集合）。
> `42`〜`44` の床・天井の議論はすべて**新**である。

以下はすべて**新（和集合）**の話。

## 2. いまあるアンサンブルを見る

```bash
python -m dc5lib.union                 # 全部
python -m dc5lib.union union5 union6   # 名前を指定
```

出るもの。

```
union6  6本（44.7。やり直しの対照 seed2 を足した）
  構成員 6 本（先頭が基準）
    基準 FinalFusion_SAM_APM_OverlapTrain    SAM+APM   v2-config   重みあり
         ...
  記録済み: docs/展望_再現率をどう上げるか.md 44.7 / 44.8（**この定義は動かさない**）
混ぜてよい条件は満たしています（ensemble / 重み）
分割の指紋 653b8cbe3d28（全員一致）
  ※ 分割を重みから確かめられない構成員が 5 本あります（素性の無い古い重み）
    → python tools/audit_splits.py --region both --conditions ...
```

**読み方。**

| 出たもの | 意味 |
|---|---|
| `基準` | 先頭の構成員。**比較の基準**になる（「基準より +0.1064」の基準）|
| `重みあり` / `**重みなし**` | 重みが SSD にあるか。無ければ測れない |
| `**ensemble: false**` | その条件は**混ぜられない**（分割か選択が他と違う）|
| `分割の指紋 …（全員一致）` | 全員が同じタイルで学習・検証・テストしている |
| `分割の指紋 … **食い違い**` | **データリーク。混ぜてはいけない** |
| `※ 分割を重みから確かめられない` | 古い重みに素性が無いだけ。**pkl から確かめる**（次節）|

> **「分からない」を「大丈夫」と読まないこと。** 素性が無い構成員が1本でもあれば、
> `tools/audit_splits.py` を通すまで分割は未検査である。

## 4. 測る — 和集合そのもの

```bash
python analysis/run_union_blind.py --region hiroshima --members <構成員…> --save --tag union6
python analysis/run_union_blind.py --region shimane  --members <構成員…> --save --tag union6
```

| 引数 | 意味 |
|---|---|
| `--members` | **先頭が基準。** 省略すると `union3` の4本になる |
| `--save` | `union_blind__<地域>__<印>.csv` に保存する |
| `--tag` | 保存名の印。**構成員が記録済みの5本と違うときは必須**（下の歯止め）|
| `--region` | `hiroshima` か `shimane`。`both` は無いので2回回す |

**広島2,964枚＋島根24,569枚を構成員の本数ぶん推論する。** 6本なら1時間以上。

> **歯止め。** 無印の `union_blind__<地域>.csv` は `44.4`／`44.6` の数字の出どころである。
> 構成員が記録済みの5本と違うのに `--tag` を付けずに保存しようとすると、
> **推論を始める前に止まる**（`guard_save`）。1時間回してから怒られることはない。

出るもの（5つの節）。

| 節 | 中身 | 読み方 |
|---:|---|---|
| 1 | 単体と和集合の箇所R/P/F、**完璧な刈り取りの上限** | **和集合の箇所F は上がらないのが普通。** 価値は上限にある（`42.1`）|
| 2 | 基準が盲だったかたまりを他が拾うか | **全員まったく光らない割合が「床」** |
| 3 | その群での各構成員のロジット最大 | **全員が負なら誰も見ていない。** 本数を増やしても届かない |
| 4 | 面積層別 | 小さい正解は和集合でも拾えないか |
| 5 | 何本が光っているか（合意数そのもの）| `J2` の設計に使う |

## 5. 測る — 部分集合の床（**推論しない。速い**）

```bash
python analysis/run_union_subsets.py --region both --tag union6 \
    --base SAM_APM DEM_APM SAM_APM_LU \
    --candidates SAM_APM_BVB SAM_APM_BLD SAM_APM_BLD_seed2
```

**4節の CSV があれば、部分集合の床は追加の推論なしで正確に出せる。**
1本でも覆い>0 なら和集合の覆いも>0 だからである。

名前は**略称**（`FinalFusion_` と `_OverlapTrain` を取ったもの）。
CSV の列名そのままで、間違えると「CSV にあるのは …」と教えてくれる。

出るもの。

| 表 | 読み方 |
|---|---|
| 手札ごとの**床の件数・割合・減り・天井** | **成否は床で見る。** 箇所F ではない（`42.9`）|
| 土台の盲の群のうち各候補が光る割合 | その構成員の「取り分」 |
| **Jaccard** | 1 に近いほど同じ場所を光らせている。低いほど手札として重ならない |
| 構成員ごとのロジット統計 | 負の割合が高いほど「見ていない」 |

> **Jaccard を「入力の違いの効き」と読む前に、種のゆらぎと比べること。**
> `44.7` では 0.482 の食い違いが仮想建物のせいに見えたが、
> **同じ条件を種だけ変えた2本でも 0.514** で区別がつかなかった。

## 6. 構成員を1本足す（**全員を推論し直さない**）

```bash
python analysis/run_union_addmember.py --region both --tag seed2 \
    --new FinalFusion_SAM_APM_BLD_seed2_OverlapTrain
```

`union_blind` の CSV は「正解のかたまり1件ごと」1行で、
**正解マスクが全構成員で同一であることを前提に付番を使い回す**。
だから足す1本だけ推論して列を継ぎ足せる（6本で1時間 → 2本で十数分）。

**行の並びが合っている証明を取る。** 記録済みの1本（既定は `BLD`）を
推論し直し、保存済みの列と照合する。

```
  覆い率の最大差            1.110e-16
  『1画素でも光る』の不一致 0 件
  **一致しました。行の並びは同じです**
```

一致しなければ**止まる**（タイルの並びか正解の作り方が変わっている）。

> **この方法で足せないもの。** `cov_*` と `lg_*` だけである。
> **`cov_union` は足せない** ── 二値マスクの論理和の覆いは、
> 構成員ごとの覆いの最大より大きくなりうる。
> **和集合の箇所R/P/F が要るなら `run_union_blind.py` を全構成員で回す。**

## 7. 新しいアンサンブルを定義する

`unions/<名前>.yaml` を1つ作る。**コードには構成員の名前を書かない。**

```yaml
name: union7
label: 7本（何のために増やしたか）
base: FinalFusion_SAM_APM_OverlapTrain      # 比較の基準になる構成員
members:
  - FinalFusion_DEM_APM_OverlapTrain
  # …
# recorded: は数字を docs に載せてから付ける
note: 何を見るための手札か。
```

| 項目 | 意味 |
|---|---|
| `base` | **先頭の構成員。比較の基準**になる |
| `members` | 残りの構成員 |
| `recorded:` | **この定義で出した数字が docs に載っている印。付いたら動かさない** |
| `note` | 床の件数など。あとで読む自分のため |

> **`recorded:` が付いた定義は構成員を変えない。** その集合で出した数字が
> docs に載っているので、変えると過去の記述が嘘になる。
> 変えたいときは**新しい yaml を作る**。

定義したら必ず通す。

```bash
python -m dc5lib.union union7   # 検査
python tools/check.py              # 既定の構成員に ensemble: false が混ざれば落ちる
```

## 8. 刈り取り（2段目）まで通す

和集合の価値は**上限**にあるので、刈り取りでどこまで届くかを測る。

```bash
python analysis/run_stage2_eval.py --union-with <構成員…> --region hiroshima --split test
```

`--union-with` に渡した構成員の和集合を1段目にして、2段目で刈り取る。
上限（`2R/(1+R)`）のどこまで届いたかで見る。

## 9. 旧側（確率を混ぜる）を動かす

```bash
python -m dc5lib.ensembles                                        # 一覧と検査
python analysis/run_ensemble_eval.py --ensemble <名前> --region hiroshima
python analysis/run_ensemble_eval.py --conditions A B C --rule mean --record
```

定義は `ensembles.yaml`。手順は `docs/練習_新しいアンサンブルを作る.md`。
`--record` で `results/evals/` に入り `metrics.csv` に載る。

> **`rule: max` は OR の連続版だが、実測では最下位だった**
> （平均 0.7102 / 最大 0.6974 / cos窓 0.7446。`docs/アンサンブルで解けるか.md` の `2.1`）。

## 10. 数字の読み方 — **成否は床で見る**

| 見るもの | 意味 |
|---|---|
| **床** | どの構成員も1画素も光らない正解の割合。**ここが下がったかで決める** |
| 天井（1 − 床）| 構成員を増やして届きうる上限 |
| 刈り取り後の上限 箇所F | `2R/(1+R)` |
| 和集合の箇所F | **上がらないのが普通。** 価値は上限にある（`42.1`）|
| Jaccard | 1 に近いほど同じ場所を光らせている |

**ゆらぎ幅より小さい差は「差が無い」。**

| | 箇所F のゆらぎ幅 |
|---|---:|
| 広島 | **0.0071** |
| 島根 | **0.0198** |

出どころは `docs/ゆらぎ幅.md`。

> **種だけ違う2本目も手札になる。** 入力を変えずに同じ条件を別の種で回しただけで、
> 床は広島 5.3% / 島根 5.1% 下がった ── **別の入力を足したときの約半分**
> （`44.8`）。手札の入力が思いつかないときの逃げ道。
> ただし**何本で飽和するかは未検査**である。

## 11. 困ったとき

| 症状 | 原因と直し方 |
|---|---|
| `アンサンブルの定義がありません` | `unions/` に yaml が無い。`python -m dc5lib.union` で一覧が出る |
| `… は ensemble: false です` | 分割か選択が他と違う条件。**混ぜられない**。いまそれは `FinalFusion_SAM_APM_BlockSplit`（別の土俵）と `Train_Hiroshima_Test_Shimane_SAM_APM`（テストで最良エポックを選んでいる）|
| `構成員の分割が食い違っています` | **データリーク。** そのまま測ってはいけない |
| `… の重みがありません` | SSD が違うか、まだ学習していない。`DC5_SSD_ID` を確かめる |
| `無印の union_blind__<地域>.csv は …` | `--tag` を付ける（`44.4`/`44.6` の出どころを守る歯止め）|
| `列がありません […]` | 略称の綴り違い。`CSV にあるのは …` を見る |
| `… の正解マスクが … と違います` | タイルの並びか正解の作り方がずれている。pkl を作り直した可能性 |
| `**照合に失敗しました。**` | 行の並びが合っていない。`run_union_blind.py` を全構成員で回し直す |
| メモリが足りない | 構成員を減らすか、地域を1つずつ回す。島根の pkl は数GBある |
