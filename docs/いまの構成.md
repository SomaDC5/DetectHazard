# いまの構成 — 最良の組み合わせの全体像

この研究でいま一番良い結果を出している構成（`Post_SAM_OL_Logit30`）を、
入力から出力まで一本で説明したもの。

- 2026-10-15 時点
- 数値はすべて `results/metrics.csv` の実測。広島はテスト2,964枚、島根は全24,569枚
- **学習は1回**。あとは推論のしかたと後処理だけ

---

## これは何で、何ではないか

**最初に誤解しやすいところを潰しておく。**

| | |
|---|---|
| **U-Net は1本だけ** | モデルは `MultiEncoderUNet` 1つ（43.58M）。学習も1回 |
| **WNet ではない** | U-Net を2つ繋いだものではない。2段目のネットワークは**まだ作っていない** |
| **アンサンブルでもない** | モデル1本。`Post_SAM_OL_Logit30` の `base` は1条件だけ |
| ⑤の刈り取りは学習しない | ロジットのしきい値と比べるだけ。**パラメータ0** |

**「2本のエンコーダ」という言い方に注意。** これは
**1つの U-Net の中に入口が2つある**という意味である。
入力が傾斜角と航空写真の2種類なので、エンコーダが
`slope_enc`（傾斜角用）と `curv_enc`（航空写真用）に分かれていて、
bottleneck で合流して**デコーダは1本**。
**U-Net が2つあるわけではない。** 出発点からずっとこの構造を使っている。

### WNet はどこまで来ているか

⑤は WNet の「2段目の位置」に入っているが、ニューラルネットではなく
数値の比較1回である。**2段目をいちばん安く作ったらどうなるかを測った**もの。

| | 状態 |
|---|---|
| 1段目 | **確定**（オーバーラップ学習 + オーバーラップ推論） |
| 2段目の設計 | **決まった**（`展望_再現率をどう上げるか.md 12.5`） |
| 2段目の実装 | **未着手** |
| 2段目が超えるべき線 | 箇所F 広島 0.7384 / 島根 0.5811 |
| 残っている伸びしろ | 上限 0.8793 に対して **77.5%** |

### アンサンブルとの比較

**この1本が、箇所F では14条件のアンサンブルを上回った。**

| 構成 | 種類 | 本数 | 面積F | 箇所F |
|---|---|---|---|---|
| **Post_SAM_OL_Logit30** | **U-Net 1本 + 後処理** | **1** | 0.7046 | **0.7472** |
| 同じモデル（刈り取りなし・通常推論） | U-Net 1本 | 1 | 0.6846 | 0.6541 |
| Ens_OverlapMix6 | アンサンブル | 6 | **0.7212** | 0.6914 |
| Ens_AllStrong14 | アンサンブル | 14 | 0.7142 | 0.6958 |
| Ens_InputDiverse4 | アンサンブル | 4 | 0.7200 | 0.6844 |

**面積F ではアンサンブルがまだ上**（0.7212 対 0.7046）。
アンサンブルは画素を平均して滑らかにするので面積に効き、
刈り取りは小さいかたまりを消すので箇所に効く。
**どちらが良いかは評価尺度で決まる**（5節）。

## 1. 各段が何を買っているか

**ひとつずつ足すと、どこで何が伸びたかが分かる。** 広島、箇所F（被覆 0.5/0.3）。

| 段 | 構成 | 箇所R | 箇所P | 箇所F | 伸び |
|---|---|---|---|---|---|
| 出発点 | 通常学習 + 通常推論 | 0.6188 | 0.6858 | 0.6506 | — |
| **+①学習** | **オーバーラップ学習** | 0.7036 | 0.6111 | 0.6541 | +0.004 |
| **+③推論** | **＋オーバーラップ推論** | **0.7846** | 0.6436 | 0.7071 | **+0.053** |
| **+⑤刈り取り** | **＋ロジットで刈る** | 0.7247 | **0.7710** | **0.7472** | **+0.040** |

**読みどころは、①が単体ではほとんど効かないこと。** 箇所F は +0.004 しか動かない。
ところが①を入れてから③を掛けると +0.053 伸びる。
**①と③は別々ではなく、組みで効いている**（`展望_再現率をどう上げるか.md 8.5`：
別々の和 +0.159 に対して実測 +0.165 で超加法的）。

①は「学習時と推論時で入力の切り方を揃える」ための下ごしらえである。
③だけを出発点に掛けても +0.047 止まりで、①と組んで初めて +0.053 になる。

⑤は**再現率を 0.060 落として適合率を 0.127 買う**操作。箇所F では +0.040。

## 2. なぜロジットを捨てずに持つのか

### 2.0 ロジットとは

**モデルの最後の層（`out_conv`）が画素ごとに出す、生の数値。**
範囲の制限が無く、−∞ から +∞ まで何にでもなる。

これを 0〜1 の「確率」として読むために、最後にシグモイド関数を掛けている。

```
確率 = σ(ロジット) = 1 / (1 + exp(−ロジット))
```

| ロジット | シグモイドを掛けた値（float32） |
|---|---|
| 0 | 0.5000000 |
| 1 | 0.7310586 |
| 5 | 0.9933072 |
| 10 | 0.9999546 |
| 20 | **1.0000000（ちょうど 1.0）** |
| 26.93 | **1.0000000（ちょうど 1.0）** |
| 41.33 | **1.0000000（ちょうど 1.0）** |

**ロジットが 20 を超えると、float32 では全部 1.0 になる。**
float32 が 1.0 と区別できる最小の差は 6.0e−8 だが、
σ(20) の 1.0 からの差は 2.1e−9 しかない。桁が足りない。

**この「潰れ」が本研究の躓きの正体だった。**
確率マップだけ見ていると、ロジット 27 のかたまりと 41 のかたまりが
**同じ「確率 1.0」に見える。** だから確率をどういじっても分けられない。

> なぜそんな大きなロジットが出るのか。損失（FocalTversky）は
> 「正解を正解と言えているか」しか見ないので、いったん当たったあとは
> ロジットをさらに大きくしても損失がほとんど減らないが、減る方向ではある。
> 止める理由が無いので、エポックを重ねるほど外へ伸びていく。

喩えるなら、**40℃ 以上を全部「熱い」としか表示しない温度計**である。
表示（確率）では 50℃ と 200℃ の区別がつかないが、
**中の目盛り（ロジット）はちゃんと違う値を指している。**

### 2.1 的中と外れでロジットが違う

ここが構成の要になっている。

| | 的中したかたまり | 外れたかたまり |
|---|---|---|
| ロジット最大値の中位数 | **41.33** | **26.93** |
| 確率に直すと | 1.0000 | 1.0000 |

**σ(41.33) も σ(26.93) も float では同じ 1.0 になる。**
シグモイドが、的中と外れを分ける情報を捨てている。

実測で、偽陽性の画素は **92〜96% が確率 0.98 超え、中位数はちょうど 1.0000**。
だから確率マップを後処理しても何も刈れず、しきい値を 0.02→0.98 と
50倍動かしても箇所Recall は 0.630→0.606 しか動かなかった。

**③で確率とロジットの両方を混ぜておき、④の二値化は確率で、
⑤の刈り取りはロジットで行う。** こうすると出発点が記録済みの値と
完全に一致するので、⑤の効果だけを切り出して測れる。

> 混ぜる空間自体はほとんど関係ない。確率を混ぜてから二値化した判定と
> ロジットを混ぜてから二値化した判定の一致は広島 99.800% / 島根 99.912%。

## 3. かたまりを分けているのは何か

⑤で使える特徴を全部測った（AUC。0.5 で情報なし）。

| 特徴量 | AUC | 使っているか |
|---|---|---|
| **ロジットの最大値** | **0.8006** | **使う** |
| ロジットの平均 | 0.7919 | 使わない（最大値とほぼ同じ） |
| かたまりの面積 | 0.7692 | 使わない（ロジットより弱い） |
| 形（周囲長/面積） | 0.2296（反転で 0.77） | **未使用。併用の余地あり** |
| 傾斜角のばらつき | 0.6770 | 使わない |
| 傾斜角の平均 | **0.5017** | 情報が無い |
| 外周までの距離 | 0.4452 | 情報が無い |

**傾斜角の平均に情報が無い**のが重要で、
「急な斜面なら本物」という単純な判定は成り立たない。
効いているのは**モデル自身の確信度**である。

形（外れたかたまりは細長い。周囲長/面積 0.314 対 0.185）は
ロジットと別系統の情報なので、併用すれば伸びる見込みがある。未実施。

## 4. しきい値 29.15 はどこから来たか

1. 広島のテストタイルを**互い違いに2つに分ける**（偶数番 1,482枚 / 奇数番 1,482枚）
2. 偶数番だけで、下位 0〜50% を捨てたときの箇所F を計算する
3. 最良だった**下位30%**を選ぶ → そのときのロジット最大値が **29.150**
4. 奇数番で測る → 箇所F 0.6974 → **0.7384（+0.0410）**

**絶対値で固定している。** 分位で持つと評価する集合が変わるたびに意味が変わる。

そして**この絶対値は地域をまたいで動かない。**

| | 箇所F |
|---|---|
| 島根、刈る前 | 0.5552 |
| 島根、**島根内でしきい値を選び直す** | 0.5801（+0.0263） |
| 島根、**広島の 29.150 をそのまま当てる** | **0.5811（+0.0259）** |

29.150 は島根のかたまりの 32.3% を捨てる位置に当たり、
広島で選んだ 30% とほぼ一致する。

## 5. 面積評価では効かない

同じ後処理を面積評価で見ると、ほとんど動かない。

| | 面積F | 箇所F |
|---|---|---|
| ③まで | 0.7035 | 0.7071 |
| ⑤まで | 0.7046 | **0.7472** |

**刈っているのが小さい偽陽性のかたまりなので、画素ではほぼ効かない。**
面積評価は画素の重み付け平均で、1000px 以上の大きいかたまりが画素の 34.6% を
占める。箇所数評価はかたまり1つを1票で数えるので、小さいものを刈ると効く。
`箇所数評価_設計メモ.md 3.5` の「尺度の重みが違う」の実例になっている。

**この構成を面積Fで評価すると良さが見えない。** 評価尺度を先に決めないと
施策の良し悪しが判定できない、という本研究の主張そのものである。

## 6. どこに何が書いてあるか

| 段 | 実装 | 定義 |
|---|---|---|
| ① 学習時の近傍貼り | `dc5lib/overlap.py` | `experiments/FinalFusion_SAM_APM_OverlapTrain/` |
| ② モデル | `dc5lib/models.py` の `MultiEncoderUNet` | config の `arch` |
| ②の損失 | `dc5lib/losses.py` | config の `train.loss`（0.7/0.3/0.75） |
| ②の学習設定 | `dc5lib/traincfg.py` | config の `train`（batch 32 / lr 1e-4 / 早期終了 100） |
| ③ 推論時の近傍貼り | `analysis/run_overlap_eval.py` の `mosaic` / `cos_window` | — |
| ③〜⑤ | `analysis/run_overlap_prune.py` | `ensembles.yaml` の `postprocess` |
| ⑤の読み手と検査 | `dc5lib/postprocess.py` | 同上 |
| 箇所数評価 | `dc5lib/instance_eval.py` | 被覆 cov_gt=0.5 / cov_pred=0.3 |

**直書きが無いか**は `tools/check.py` が止める。

### 再現するには

```bash
# 記録つきで評価しなおす（学習は不要。重みは dc5-data/weights/ にある）
python analysis/run_overlap_prune.py --postprocess Post_SAM_OL_Logit30 --region hiroshima --record
python analysis/run_overlap_prune.py --postprocess Post_SAM_OL_Logit30 --region shimane  --record

# 定義の一覧
python -m dc5lib.postprocess
```

## 7. この構成の限界

| | |
|---|---|
| 再現率の天井 | ⑤は刈るだけなので、**①③で出せなかった箇所は永久に出ない**（箇所R 0.7846 が上限） |
| 残っている伸びしろ | 完璧に刈れたときの上限は箇所F 0.8793。しきい値1本で取れたのは **22.5%** |
| 島根では刈る対象が多い | 外れたかたまりが 45.9%（広島 35.6%）。汎化先では誤検出がそれだけ多い |
| 実運用には足りない | 箇所R 0.72（刈った後）では見逃しが残る。`展望_再現率をどう上げるか.md 7.3` |

### 確かめていないこと

- DEM+APM 版（広島の単体最良 箇所F 0.7112）には⑤を未適用
- アンサンブルには⑤を未適用。確率を平均するのでロジットが残らない
- 形の特徴（3節）を併用していない
- 複数シードで測っていない
- 記録した広島の箇所F 0.7472 は全タイルに同じしきい値を当てた値で、
  しきい値はその半分で選んでいる。**別タイルだけで測った値は 0.7384**。
  論文の表に出すときはどちらを使うか決めること
