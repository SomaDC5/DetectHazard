## 1. 原則

1. **設定の出どころは `config.yaml` だけ。** ノートブックに値を書かない
2. **ノートブックは「読む・呼ぶ・見る」だけ。** 処理は `dc5lib` に置く
3. **重みは自分がどう学習されたかを持つ。** 重みファイルだけで素性が分かる
4. **検査で守る。** 人の注意力に頼らない。ずれたら `tools/check.py` が落ちる

> **1と2が守られていれば、`設計図_現状.md` の `6` の1〜6は構造的に起きない。**
> 3が守られていれば8（学習時の設定が分からない）が消える。
> 4が無いと、守られているかどうかが分からない。

## 2. 層をどう変えるか

**足すもの（4ファイル）。**

| | 役割 | 公開する関数 |
|---|---|---|
| `dc5lib/pipeline.py` | pkl を読む → マスク前処理 → 分割 → `Dataset` / `DataLoader` | `build_loaders(cond, region)` → `Loaders` |
| `dc5lib/train.py` | 学習ループ・早期終了・曲線の保存・重みの保存 | `fit(cond, loaders, hooks=None)` → `History` |
| `dc5lib/ckpt.py` | 重みの保存と読み出し。**素性を同梱する** | `save(path, model, meta)` / `load(path)` / `meta_of(path)` |
| `dc5lib/evaluate.py` | テストの画素評価・箇所評価をまとめて呼ぶ | `evaluate(cond, loaders, split="test")` |

**触らないもの。** `paths` / `registry` / `traincfg` / `models` / `losses` /
`inputs` / `overlap` / `data` / `instance_eval` / `vbuilding`。
**既存の `analysis/*.py` も触らない**（評価の数字が動くと `42`〜`44` が崩れる）。

### 2.1 `pipeline.build_loaders` が返すもの

```
Loaders
  train / val / test        DataLoader
  split                     {"fingerprint", "train": [...], "val": [...], "test": [...]}
  fields                    {"terrain": (形, dtype, 平均), "airphoto": ..., "third": ...}
  n_tiles                   pkl のタイル数
```

**`split.fingerprint` が `audit_splits.py` と同じ指紋である**ことが要点。
これで「この学習はあの学習と同じ分割か」が照合できる。

### 2.2 `train.fit` の中にあるもの

- 学習ループ（エポック・バッチ・勾配）
- **早期終了**（`CFG.early_stop_patience`。`設計図_現状.md` の `5.1` の23本の穴）
- 検証F値が最良のエポックで重みを保存（`model_selection` の約束）
- 曲線を `paths.curve_path(CONDITION)` に**毎エポック flush して書く**
  （`BVB`・`BLD` で9行ぶん書き遅れた件がこれで消える）
- `hooks` で差し込める：`on_epoch_end(ep, metrics)` と
  `loss_fn(out, target)` の差し替え。**細工はノートブックからできる**

## 6. 既存条件の扱い — config に素性を書く

**再学習はしない（②は (a)）。** 代わりに config に2つ足す。

```yaml
protocol: v1-notebook        # どの世代の手順で学習したか
ensemble: true               # アンサンブルに入れてよいか
```

| `protocol` | 意味 | 本数 | `ensemble` |
|---|---|---:|---|
| `v1-notebook` | 旧世代。`CFG` が無く直書き。`6:2:2` は他と一致 | 26 | `true` |
| `v1-8:2-testselect` | 旧プロトコル。検証分割なし・**テストで選択** | 3 | **`false`** |
| `v1-blocksplit` | 空間ブロック分割。**別の土俵** | 1 | **`false`** |
| `v2-config` | いまの世代。`CFG` 経由。`seed` は条件によって未固定 | 25 | `true` |
| `v3-base` | 基盤ノートブック。全項目が config 経由 | 0 | `true` |

**`v1-notebook` を `ensemble: true` にするのは実測に基づく**
（`設計図_現状.md` の `8`：分割が一致している）。ただし
**乱数は未固定**なので、`seeded: false` を別に持つ。

### 7.1 基盤ノートブックをどう検証するか

**いまの `BLD` の曲線とは一致しない。** 既存は `torch.manual_seed` が
無い状態で学習したので、**同じ設定でも初期値が違う**（`ゆらぎ幅.md` の `8`）。
だから「曲線が一致するか」では検証できない。代わりにこう見る。

| 見るもの | 合うべき値 |
|---|---|
| 分割の指紋 | 並び `a75ad23bad3e` / 分割 `653b8cbe3d28`（広島）。**既存と一致しなければ設計が違う** |
| 学習・検証・テストの枚数 | **8,889 / 2,963 / 2,964**（警戒区域あり 14,816 のうち。`設計図_現状.md` の `8` の訂正を参照）|
| 各入力の形・dtype・平均 | **学習タイルから256枚で測った値。** 広島 `BLD` は 傾斜 20.62199／写真 96.41599／建物2面 4.15054（>0 が 2.90%）／正解 0.08882。以前ここに書いた「建物 0.10271」は少数枚の試運転の値で、母数が違う |
| モデルの引数の数と総パラメータ | 3入力 / 56.12M |
| 1バッチ目の損失 | 既存の試運転は 0.82611。**乱数が違うので一致はしない**。0.8 前後なら良い |
| 短く回したときの検証F | 既存の最良 0.7057 に対し、**帯（0.0071）の中に入るか** |

**「一致」を求められるのは分割と形だけである。** そこを合わせ、
学習の結果は帯で見る。**ここを曖昧にしないために先に書いておく。**
