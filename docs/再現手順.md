# 再現手順 — どのコマンドでどの数字が出るか

`展望_再現率をどう上げるか.md` と `ゆらぎ幅.md` に書いた数字を、
自分で動かして確かめるための対応表。

- 作成 2026-10-21
- `使い方.md` が**ファイルの役割と作業手順**、こちらは**数字の再現**
- 学習が要るものと要らないものを分けてある。**要らないものから試すのが速い**

---

## 0. 前提

```bash
conda activate mayo          # lab-windows の環境名（environment.yml は dc5）
cd ~/dc5/DetectHazard
python -m dc5lib.paths       # 外部SSD が見つかるか
python tools/check.py        # 構成の健全性（「問題: なし」が出ればよい）
```

出力はすべて `dc5-data/cache/analysis/` に出る（数GBになるのでリポジトリに入れない）。

| 置き場所 | 中身 |
|---|---|
| `cache/analysis/tiles/` | 1タイル1行の混同行列（面積評価のもと） |
| `cache/analysis/instances/` | 1タイル1行の箇所数（箇所数評価のもと） |
| `cache/analysis/report/` | 条件横断の集計 |
| `cache/stage2/` | 2段目のかたまりデータ（npz、200〜240MB） |
| `dc5-data/weights/<名前>/best_model.pth` | 重み |

> **文字化けするとき。** Windows のコンソールが cp932 だと日本語が崩れる。
> `set PYTHONIOENCODING=utf-8` を先に入れるか、出力をファイルに落として読む。

## 1. いちばん良い構成だけ確かめる（最短経路）

**最良は `Post_Union3Agree_Stage2`（広島 箇所F 0.7784）。**
3本の和集合 + 合意数チャネル + 2段目CNN。

```bash
# 定義を見る
python -m dc5lib.postprocess

# 1) 2段目のかたまりデータを作る（1段目3本の推論。GPU で約3分）
python analysis/run_stage2_train.py --build --splits val \
    --stage1 FinalFusion_SAM_APM_OverlapTrain \
    --union-with FinalFusion_DEM_APM_OverlapTrain FinalFusion_SAM_APM_LU_OverlapTrain \
    --agree

# 2) 2段目を学習（数分）
python analysis/run_stage2_train.py --train --name Stage2_Union3Agree_s1 \
    --union-with FinalFusion_DEM_APM_OverlapTrain FinalFusion_SAM_APM_LU_OverlapTrain \
    --agree --seed 1 --split-seed 42

# 3) しきい値を検証split で選ぶ
python analysis/run_stage2_eval.py --model Stage2_Union3Agree_s1 \
    --union-with FinalFusion_DEM_APM_OverlapTrain FinalFusion_SAM_APM_LU_OverlapTrain \
    --split val

# 4) テストで測る（3 で出たしきい値を渡す）
python analysis/run_stage2_eval.py --model Stage2_Union3Agree_s1 \
    --union-with FinalFusion_DEM_APM_OverlapTrain FinalFusion_SAM_APM_LU_OverlapTrain \
    --split test --thr 0.50
```

**期待される出力**（4 の末尾）

```
刈った後 箇所R 0.7808 / P 0.7781 / F 0.7794
```

`--region shimane` を付けると島根（全24,569枚）になる。
**しきい値は広島で選んだ値をそのまま当てる**のが作法（`13.2`・`23.9`）。

## 3. 学習が要るもの

ノートブックで学習する。1本あたり数時間。

```bash
# 条件を作る（config.yaml とノートブックが生える）
python tools/new_experiment.py <名前> --from <ひな形の条件> --loss <損失>
# ノートブックに CFG・乱数固定・早期終了・追加学習の配線を入れる
python tools/wire_config.py <名前>
# experiments/<名前>/Keisya_airPhoto_final6.ipynb を Jupyter で回す
```

| 条件 | 何を確かめるため | 場所 |
|---|---|---|
| `FinalFusion_SAM_APM_seed1/2/3` | ゆらぎ幅（帯） | `ゆらぎ幅.md` |
| `FinalFusion_SAM_APM_OL_LogitHinge` | ロジット空間の損失（**負の結果**） | `20` |

### 3.1 ロジットヒンジを自分で試すなら

```bash
python -m dc5lib.losses FinalFusion_SAM_APM_OL_LogitHinge   # 損失の中身
python -m dc5lib.traincfg FinalFusion_SAM_APM_OL_LogitHinge # 学習設定
```

`train.init_from` を書くと**既存の重みから追加学習**になる（既定 None でゼロから）。
ただし `20.12` のとおり**追加学習は交絡が大きいので使わないほうがよい。**

## 4. 2段目のバリエーション

すべて `run_stage2_train.py` のフラグで切り替わる。
**学習は数分**なので、シードを振って帯を測るのが安い。

| フラグ | 構成 | 広島 箇所F | 場所 |
|---|---|---|---|
| （なし） | 近傍 64×64 のみ・6ch | 0.7525 | `14` |
| `--wide` | + 広域 1,147m | 0.7512（上がらない） | `15` |
| `--wide --landuse` | + 広域 + 土地利用 | 0.7465（下がる） | 同 |
| `--union-with A` | 2本の和集合 | 0.7639 | `22` |
| `--union-with A B` | 3本の和集合 | 0.7705 | `23` |
| `--union-with A B --agree` | **+ 合意数チャネル** | **0.7784** | `24` |

```bash
# 帯を測る（初期化だけ振る。分割は固定）
for s in 1 2 3; do
  python analysis/run_stage2_train.py --train --name Stage2_X_s$s \
      --seed $s --split-seed 42 <構成のフラグ>
done
```

| 2段目の帯 | 値 | 場所 |
|---|---|---|
| 初期化のみ（分割=42固定）・最良しきい値 | **0.0031** | `17.2` |
| 分割も振る・最良しきい値 | 0.0048 | 同 |
| **しきい値 0.45 固定** | **0.0231** | `17.3` |

> **2段目を再学習したら、しきい値は必ず測り直すこと。**
> 最良点は安定だが、そこに至るしきい値が 0.35〜0.50 で動く。
> 固定したままだと 0.023 落ちる。

## 6. 気をつけること

| | |
|---|---|
| **帯で判定する** | 差を見たら必ず `run_band.py` の幅と比べる。指標と地域で11倍違う |
| **しきい値は別タイルで選ぶ** | 同じタイルで選んで測ると甘い値が出る（広島で 0.7472 対 0.7417） |
| **2段目は AUC で選ばない** | AUC が最良でも箇所F が最悪のことがある（`15.6`・`23.6`） |
| **和集合は3本で折り返す** | 4本目は箇所R を +0.0077 足すが外れが増えて相殺（`23.3`） |
| **既存条件を壊さない既定値** | `FocalTverskyLoss` の `clamp` は 10.0、`N_CH` は 6、`init_from` は None |
| **`--force` を忘れる** | `run_inference.py` は済んだ条件を飛ばす |
| メモリ | 和集合は pkl を1本ずつ読んで解放している。島根3本で 6〜8GB 使う |

## 7. この文書で確かめていないこと

- **島根の2段目の帯が未測定。** 島根で 6ch → 7ch の差 +0.0035 を判定できない
  （`24.10`）。切り分けるには島根で3シードずつ回す（推論6回、1時間ほど）
- `run_band.py` と `run_logit_diag.py` は 2026-10-21 に後から書いたもので、
  文書の数字は**元は使い捨てのコードで出していた**。
  値が一致することは確認したが、別の条件群で回した例はまだない
- `run_hazard_map.py` は lab-windows では動かない（rasterio が無い）
- 学習の再現はビット単位では一致しない（cuDNN の非決定性。`ゆらぎ幅.md`）

| **SaveAs2 に相対パスを渡すと迷子になる** | Word 自身の既定フォルダ（Documents）に保存される。絶対パスにすること |
| **段落を1つずつ Add すると潰れる** | 全行を `\r` でつないで `Content.Text` に一度で入れる |
| **`ConvertToTable` は段落の数を変える** | セルが段落になるので、段落番号で当てる処理（太字・数式）を**先に**済ませる。逆にすると本文を数式に変えてしまう |
| **書体では数式を見分けられない** | 日本語を含む数式（`F_面積` など）は書体が混在して `Font.Name` が取れない。専用の段落スタイル「数式」で見分ける |
