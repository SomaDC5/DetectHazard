# 次の手 — 「文脈不足」と「クラス不均衡」をどう扱うか

`失敗の所在.md` で分かった「64x64 に信号は残っているが鋭くない」の正体を特定し、
あわせてクラス不均衡への対処（疑似データを含む）を検討したもの。

- 測定 2026-10-01 / `lab-windows` / 広島
- 結論を先に書くと、**足りないのは解像度ではなく文脈**。
  そして**この研究の問題は「正例が少ないこと」ではなく「負例の多様性が足りないこと」**

---

## 1. 「鋭くない」の正体は受容野の不足

`失敗の所在.md` 3.2 で、深層監督の補助ヘッドは TP=0 タイルでも 0.1447 を出すのに
（本体は 0.0001）、それを OR で統合すると箇所Precision が 0.750 → 0.300 に崩壊した。
**高Recall・低Precision** であり、「当たってはいるが、当てずっぽうも多い」状態。

理由を測った。

| | 値 |
|---|---|
| 64x64 の1画素 | **8.96 m** |
| `aux_head` の受容野（Conv3x3 → Conv1x1） | **3x3 = 26.9 m四方** |
| `slope_enc2` までの受容野 | 約 99 m |
| 箇所の典型サイズ（タイル平均の中央値 328px） | 約 81 m四方 |

**補助ヘッドは 27 m 四方しか見ずに「ここは警戒区域か」を判定している。**
警戒区域の指定は斜面全体と保全対象の有無で決まるので、この窓では原理的に足りない。

> 解像度の問題ではない。64x64 は 8.96 m/画素で、81 m 四方の箇所なら 9x9 画素ある。
> 足りないのは、その周囲に何があるかという文脈。

---

## 2. 文脈を増やす案

### 案A ‧ 64x64 の段に dilated convolution（ASPP）を入れる — 本命

プーリングせずに受容野を広げる。dilation 1/2/4/8 を並列に並べれば、
64x64 の解像度のまま **27 m 〜 215 m** の文脈が同時に取れる。DeepLab 系の標準手法。

**`U-Net構造改良・損失関数アイデアまとめ.docx` 6章の「TransUNet(94M)が Final(43.6M)より
有意に悪い（−0.0069, p=0.002）」は、この案の反証にならない。**
TransUNet の大域文脈は**ボトルネック(8x8)**にあり、解像度を失ったあとに文脈を足している。
dilated conv は**解像度を保ったまま**文脈を取るので別物。

### 案B ‧ 出力ストライドを下げる（プーリングを1段減らす）

16 → 8 にすればボトルネックが 16x16（35.9 m/画素）になり、300px 以下の箇所が
サブピクセルでなくなる。メモリは約4倍。

### 案C ‧ 補助ヘッド自体を厚くする — 最も安い検証

3x3 を1層ではなく、dilation 付き3層にする。**案Aが効くかを数時間で確かめられる。**
補助ヘッドの Precision が上がれば「文脈不足が原因」という診断が確定する。

**C → A の順を推奨。** C は既存の構成に小さなヘッドを足して再学習するだけで、
診断として機能する。

## 3. クラス不均衡 — 問題の立て方が違う

### 3.1 実測

| 学習集合 | 正例の割合 |
|---|---|
| 警戒ありタイルのみ（従来の既定） | **9.33%** |
| bg_ratio=0.1 | 5.22% |
| 背景込み全38,148枚（実運用の分布） | **1.05%** |

### 3.2 正例を重くする手は効かない（bg_ratio の評価は 10-02 に訂正）

> **2026-10-02 訂正。** 初版はここに「bg_ratio=0.1 が 面積F +0.0558 / 箇所F +0.0654 で
> これまでで最大の改善」と書いていたが、**これはテスト集合の汚染による誤り**だった
> （`実験のまとめ.md` 8節）。正しくは下表のとおり、F値はむしろ下がる。

| | 広島 面積F（警戒のみ） | 広島 箇所F（警戒のみ） |
|---|---|---|
| bg=0（出発点） | 0.6727 | 0.6506 |
| bg_ratio=0.1 | 0.6636（**−0.009**） | 0.6252（**−0.025**） |

正例を重く扱う手法も効かなかった。しかも**非単調**で、強めると下がる。

| 施策 | 広島 面積F | 広島 箇所F |
|---|---|---|
| 箇所正規化損失 p=0.5 | 0.6763（+0.0036） | 0.6596（+0.0090） |
| 箇所正規化損失 p=1.0 | 0.6692（−0.0035） | 0.6378（−0.0128） |

**「正例が少ないこと」が問題という見方は、依然として支持されない。**
正例を重くしても ±0.01 以内で、しかも強めると悪化する。
理由は勾配の飽和で、被覆0.5 を落ちた箇所の 69.4% は「1画素も出ていない」状態にあり、
重みを8倍しても勾配は 0 のまま（`層ごとの効き方.md` 2節）。

**一方「負例の多様性が足りない」のほうは、根拠が訂正前より弱くなった。**
いま残っている根拠は、bg_ratio が F値ではなく**背景での過検出だけを減らした**ことである。

| | 島根の背景での過検出画素 |
|---|---|
| bg=0 | 2,234,652 |
| bg_ratio=0.1 | 2,016,145（−218,507） |

狙い（背景を棄却させる）自体は達成されているが、警戒ありタイルの F値には結びついていない。
**「棄却を学ぶ」ことと「警戒区域を当てる」ことがトレードオフになっている**、
というのが訂正後の読み。負例を増やす方向を続けるなら、この両立が課題になる。

## 4. 疑似データの検討

結論として、**この研究では優先度が低い。**

| 案 | 評価 |
|---|---|
| **Copy-Paste 拡張** | 条件つきで可。ただし平坦地に急斜面を貼ると物理的にあり得ない地形になり、偽の手がかりを学ぶ。やるなら傾斜帯が近いタイル間に限定する |
| **合成地形の生成** | **成立しない。** DEM は生成できるが、ラベルは「行政が指定したかどうか」で、保全対象（人家等）の有無で決まる。地形から合成できない |
| **擬似ラベル（self-training）** | **適用先が無い。** 警戒区域は公開された行政情報なので「ラベルのない領域」が存在しない。他県に広げてもラベルは手に入る |
| **島根データを学習に混ぜる** | **疑似データより確実。** 本物のデータで、地域の多様性が増える。bg_ratio が効いた理由と同じ方向 |
| **bg_ratio を上げる** | **最も安い。** bg30 / bg50 は作成済みで未実行 |

## 5. 優先順位

> **2026-10-02 訂正。** 初版の優先順位は bg_ratio が最大の改善だという前提で組んでいた。
> その前提が崩れたので、下表に組み直した。2・4（ASPP）は実施済みで、
> 補助ヘッド単体は F +0.119 と大きく改善したが本体は +0.009 止まりだった。

| 順 | やること | 根拠 | コスト |
|---|---|---|---|
| 1 | **オーバーラップ推論を島根で検証** | 広島で箇所F +0.047〜+0.060。唯一効いた施策。汎化の確認が要る | 小 |
| 2 | **窓数・統合の重みを詰める** | 9窓・cos窓しか試していない。統合規則だけで 0.047 動く | 小 |
| 3 | **タイルサイズを 256 に上げる** | 外周16px帯が 43.75% → 23.4%。失敗の61%がそこ | 中 |
| 4 | **島根を学習に混ぜる** | 疑似データより確実。地域の多様性が増える | 中 |
| 5 | bg30 / bg50 を回す | bg10 が効かなかったので優先度は下げた | 条件は作成済み |

### これまでの実績（広島、2026-10-02 訂正後）

bg=0 の条件は警戒のみ2,964枚で出発点 `FinalFusion_SAM_APM`（0.6727 / 0.6506）と比較。
bg>0 の条件は集合が違う（3,430枚）ので、bg10（0.6636 / 0.6252）を基準にした差を併記する。

| 施策 | 面積F | 箇所F | 基準 | 学習 |
|---|---|---|---|---|
| **オーバーラップ推論** | +0.021〜+0.026 | **+0.047〜+0.060** | 各条件の従来推論 | **不要** |
| データ拡張 | +0.0247 | +0.0136 | 出発点 | 要 |
| 箇所正規化損失 p=0.5 | +0.0036 | +0.0090 | 出発点 | 要 |
| 監督つき Attention（ブランチ別） | +0.0049 | +0.0017 | 出発点 | 要 |
| 箇所正規化損失 p=1.0 | −0.0035 | −0.0128 | 出発点 | 要 |
| bg_ratio=0.1 | −0.0091 | −0.0254 | 出発点 | 要 |
| 深層監督 1段 | +0.002 | +0.015 | bg10 | 要 |
| 深層監督 3段 | +0.002 | +0.016 | bg10 | 要 |

**推論側が効き、モデル側は効いていない**という傾向は訂正後も変わらない。
変わったのは**データ側（bg_ratio）も効かなかった**という点で、
訂正前の「データ側と推論側が効く」という読みは成立しない。
