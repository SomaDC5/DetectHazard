# 層ごとの効き方 — どの部品が何をして、何を壊したか

これまでの実験を「U-Net のどこを触ったか」で並べ直したもの。
`実験のまとめ.md` が時系列・施策別なのに対し、こちらは部品別。

- 数値は広島・警戒のみ（bg=0 は2,964枚、bg>0 は2,946枚）。2026-10-02 訂正後
- 「bg10 比」は bg10 を出発点としたときの差。構造の良し悪しはこちらで見る
- 「出発点比」は `FinalFusion_SAM_APM`（0.6727 / 0.6506）との差

## 1. 入力データ — bg_ratio

**やったこと**: 警戒区域を含まない背景タイルを、学習データに1割混ぜた。

| | 効果 |
|---|---|
| ✅ 効いた | 背景タイルでの過検出が減った（島根の背景で 2,234,652 → 2,016,145 画素） |
| ❌ 悪化した | 警戒ありタイルの F値（面積 −0.009 / 箇所 −0.025） |

**解釈**: 狙い（背景を棄却させる）自体は達成されている。ただし「棄却を学ぶ」ことと
「警戒区域を当てる」ことはトレードオフになっており、後者が下がった。
正例の割合が 9.33% → 5.22% に下がったぶん、正例側の学習が弱まったと見るのが素直。

**副作用**: 背景タイルでの誤検出は、画素数は減ったが**出てしまうタイル数は増えた**
（島根で 3,848 → 5,456枚）。過検出が薄く広がる方向に変わっている。

---

## 2. 損失関数 — 箇所正規化

**やったこと**: 正解の箇所ごとに重みの総和が揃うようにして、小さい箇所の
過小評価（8.45倍）を打ち消す。

| p | 面積F | 箇所F | 箇所Recall |
|---|---|---|---|
| なし | 0.6727 | 0.6506 | 0.6188 |
| 0.5 | 0.6763 | 0.6596 | 0.6463 |
| 1.0 | 0.6692 | 0.6378 | 0.5953 |

| | 効果 |
|---|---|
| ✅ 効いた | p=0.5 で箇所Recall +0.028。意図した向き |
| ❌ 悪化した | p=1.0 で箇所Recall −0.024。**ベースより下** |

**解釈**: **非単調**。機構が正しく効いているなら単調に上がるはずで、そうなっていない。
理由は `展望.md` 2節(b) のとおり、落ちた箇所の69.4%は「1画素も出ていない」状態で、
ロジットが負に張り付いており**勾配が飽和している**。重みを8倍しても勾配は0のまま。
重み付けが効くのは「あと少しで届く画素」だけで、そこは全体の5.9%しかない。

## 3. skip2（64x64）に監督を足す — 深層監督1段

**やったこと**: `cat([slope2, curv2])`（64x64, 256ch）に小さなヘッドを付け、
正解マスクを 1/2 に落としたものを教師にする。

| | 効果 |
|---|---|
| ✅ 効いた | 箇所F +0.015、箇所Recall +0.018。100〜3000px の見逃しが一貫して減った |
| ❌ 悪化した | 面積Precision −0.017。塗り広げ（予測面積比 1.512 → 1.598） |

**箇所サイズ別の見逃し**（bg10 比）

| サイズ | 箇所数 | 差 |
|---|---|---|
| 〜50px | 119 | +3（ノイズ） |
| 50-100 | 378 | −6 |
| 100-300 | 3,423 | **−27** |
| 300-1000 | 4,141 | **−25** |
| 1000-3000 | 840 | **−17** |
| 合計 | | **−71** |

**解釈**: 監督を入れた段の解像度で表現できるサイズ（100〜3000px）には効く。
50px 以下は 64x64 で 4x4 画素しかなく届かない。

---

## 4. skip1,2,3 に監督を足す — 深層監督3段

**やったこと**: 128/64/32 の3段に監督を入れ、補助損失の重みを段数で割って
合計 λ=0.5 を保った。

| | 効果 |
|---|---|
| ✅ 効いた | bg10 比では1段版とほぼ同じ（面積F +0.002 / 箇所F +0.016） |
| ❌ 悪化した | **1段版で効いていた 100〜3000px の改善が失われた**。TP=0 タイルが最多（401枚） |

**解釈**: **64x64 への配分が 0.5 → 0.167 に減り、効いていた監督が薄まった。**
128x128 の段を足した狙いは 50px 以下だったが、該当は119箇所しかなく、
薄まった損のほうが大きい。**段を増やすなら総圧力も増やす必要がある。**

---

## 5. skip2 を監督つきで変調する — 監督Attention

**やったこと**: 深層監督の存在マップを sigmoid に通し、`skip * (1 + attn)` で
スキップ特徴を増幅する（MPRNet の Supervised Attention Module と同じ形）。

| | 効果 |
|---|---|
| ✅ 効いた | **箇所F +0.020 で構造改良のなかで最良**。箇所Recall も最高クラス |
| ❌ 悪化した | **塗り広げが最大**（予測面積比 1.512 → 1.706、飲み込み 0.206 → 0.264） |

**解釈**: 変調が `x * (1 + sigmoid)` の残差型なので、**増幅する方向にしか働かない。**
存在マップが高い場所を強めるため、予測が広がる。箇所評価では被覆が稼げて得だが、
面積Precision は落ちる。**「出す方向」には効くが「出さない方向」には効かない。**

### 5.1 ブランチ別にして bg=0 で回す（2026-10-02 追記）

**やったこと**: 監督と変調を concat の前に移し、地形量ブランチと航空写真ブランチで
別のヘッドを持たせた（`SupAttnPerBranchMultiEncoderUNet`）。bg_ratio=0 なので
テスト集合が出発点と同一の警戒のみ2,964枚になり、**直接比較できる。**

| | 面積F | 箇所F | 箇所R | 箇所P |
|---|---|---|---|---|
| 出発点 `FinalFusion_SAM_APM` | 0.6727 | 0.6506 | 0.6188 | 0.6858 |
| ブランチ別・bg=0 | **0.6776** | 0.6523 | 0.6421 | 0.6628 |
| 差 | **+0.0049** | +0.0017 | **+0.0233** | **−0.0230** |

| | 効果 |
|---|---|
| ✅ 効いた | **構造変更として初めて出発点の面積Fを上回った**（+0.0049） |
| ❌ 悪化した | 島根で面積F −0.0063 / 箇所F −0.0024。**汎化していない** |
| ❌ 悪化した | 箇所Recall +0.023 を箇所Precision −0.023 でほぼ打ち消している |

**解釈**: 箇所R と箇所P がほぼ同じ大きさで入れ替わっており、5節の
「増幅する方向にしか働かない」性質はブランチ別にしても変わっていない。
面積F の +0.0049 はゆらぎ幅（0.003〜0.005）の上端に重なり、既存4構造の帯
（0.672〜0.681）の中にある。**bg10 版では bg10 比 +0.020（箇所F）で
bg10系7条件の最良だったが、bg=0 では +0.0017 に縮んだ。**
この機構の見かけの効きは bg_ratio を入れた状態に固有のもので、
背景混入で弱まった正例側の学習を存在マップの増幅が埋めていた、と読める。

## 6. skip2 に文脈を足す — ASPP

**やったこと**: skip2 に dilation 1/2/4/8 + 大域プーリングを残差で足し、
受容野を 26.9 m から最大 573 m に広げた。

| | 効果 |
|---|---|
| ✅ 効いた | **面積F +0.009 で構造改良のなかで最良**。TP=0 タイルが最少（287枚） |
| ✅ 効いた | **補助ヘッド単体の F が 0.5754 → 0.6944（+0.119）** |
| ❌ 悪化した | 箇所F は +0.008 止まりで監督Attn（+0.020）に負ける |

**補助ヘッド単体の性能**（64x64 の存在マップを直接評価）

| | 受容野 | R | P | F |
|---|---|---|---|---|
| 深層監督のみ | 26.9 m | 0.6200 | 0.5367 | 0.5754 |
| **ASPP** | 573 m まで | 0.7139 | 0.6759 | **0.6944** |

**解釈**: **「文脈不足」という診断は確定した。** 受容野を広げると補助ヘッドは
大きく改善する。ところが本体の改善は +0.009 止まりで、補助ヘッドの +0.119 に
まったく見合わない。**スキップ接続の質はデコーダにとって律速ではない。**

---

## 7. ボトルネックの解像度を上げる — ストライド8

**やったこと**: pool4 を通さず、ボトルネックを 8x8（71.7 m/画素）ではなく
16x16（35.8 m/画素）で計算する。受容野は dilation=2 で補う。

| | 効果 |
|---|---|
| ✅ 効いた | 箇所F +0.014。面積Recall が最高クラス（0.7238） |
| ❌ 悪化した | **ASPP 単体（+0.009）を面積Fで下回る（+0.007）** |

**解釈**: ASPP の実験から「デコーダが信用しているのはボトルネック経路」と読んで
設計したが、**その読みは支持されなかった。** 解像度を2倍にしても ASPP 単体を
超えない。6節とあわせると、**スキップ側もボトルネック側も律速ではない**ことになる。

> 訂正前は「構造変更で唯一 bg10 を超えた」としていたが、これはテスト集合の
> 汚染によるもの。正しい集合では ASPP のほうが上。

## 8. 推論のやり方を変える — オーバーラップ

**やったこと**: 3x3 の近傍タイルを貼り合わせ、64px ずつずらした9窓で推論し、
中心ほど重い cos 窓で平均する。**学習は一切しない。**

| 条件 | 従来 箇所F | オーバーラップ | 差 |
|---|---|---|---|
| FinalFusion_SAM_APM | 0.6513 | 0.6984 | **+0.047** |
| bg10 | 0.6135 | 0.6736 | **+0.060** |
| bg10 + ASPP + ストライド8 | 0.6250 | 0.6780 | +0.053 |

| | 効果 |
|---|---|
| ✅ 効いた | **どの重みでも +0.047〜+0.060。学習側のどの改良より一桁大きい** |
| ❌ 注意 | 統合規則を誤ると逆効果（単純平均 0.7102 / 最大 0.6974 / cos窓 0.7446） |

**解釈**: TP=0 タイルの61%は「正解が全部タイル外周16px帯」だった。
窓をずらすとその断片が中心に来るので、境界で切れた箇所を拾える。
**モデルの表現力ではなく、タイルの切り方が最大のボトルネックだった。**

## 9. 部品別の総括

### 効いた軸

| 軸 | 効き方 |
|---|---|
| **タイルの切り方（推論）** | 箇所F +0.047〜+0.060。**唯一、桁が違う** |

### 効かなかった軸（いずれも ±0.01 以内）

| 軸 | なぜ効かないか |
|---|---|
| スキップ接続の品質 | ASPP で補助ヘッドが +0.119 改善しても本体は +0.009（6節） |
| スキップ接続の読み出し | 補助ヘッドを本体に統合すると箇所Precision が 0.750 → 0.300 に崩壊（4節） |
| ボトルネックの解像度 | 2倍にしても ASPP 単体を超えない（7節） |
| 監督を入れる段の数 | 増やすと配分が薄まって逆効果（4節） |
| 損失の重み付け | 勾配が飽和している箇所には届かない（2節） |
| エンコーダの表現力 | TP=0 タイルでも活性コントラストは同等以上（3.1節） |
| 融合位置・注意機構・Transformer・パラメータ量 | 既存4構造が 0.672〜0.681 に収まる |

### 共通する副作用 — 塗り広げ

監督を入れる系統はすべて予測が広がる。

| 条件 | 予測面積/正解面積 | 飲み込まれた正解 |
|---|---|---|
| bg10 | 1.512 | 0.206 |
| + 深層監督1段 | 1.598 | 0.231 |
| + 深層監督3段 | 1.573 | 0.252 |
| + ASPP | 1.659 | 0.262 |
| + ストライド8 | 1.665 | 0.251 |
| + 監督Attention | **1.706** | **0.264** |

**箇所Recall を上げる改良は、例外なく予測面積を増やしている。**
運用帯（1.4〜1.6）の上限に近く、監督Attn は超えている。
箇所F が上がっても、面積Precision を犠牲にしているぶんが大きい。

## 10. ここから言えること

**U-Net の内部をどう触っても ±0.01 しか動かない。** 触った場所は
エンコーダ・スキップ・ボトルネック・デコーダへの入力・損失・入力データの6か所で、
どれも律速ではなかった。

一方、**タイルの切り方を変えるだけで +0.05 動く。** これは
「モデルが悪い」のではなく「問題の与え方が悪い」ことを意味する。

残っている方向は2つしかない。

1. **問題の与え方を変える** — オーバーラップ推論の延長。窓数・重み・タイルサイズ
2. **入力に無い情報を足す** — 建物・土地利用。TP=0 の60%は傾斜コントラストが負で、
   地形からは答えが出ない（`失敗の所在.md` 2節）
