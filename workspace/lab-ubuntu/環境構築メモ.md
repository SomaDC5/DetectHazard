# 研究室PC 1（Ubuntu）の環境構築メモ

2026-09-30 に構築。`HirokaneZemi01` / Ubuntu 24.04.4 / RTX 5080 / RAM 31GB。

---

## 1. いちばん大事なところ — PyTorch の入れ方（README を直した）

構築時点の README と `docs/使い方.md` には、CUDA ありの場合こう書いてあった。

```bash
conda install pytorch pytorch-cuda=12.1 -c pytorch -c nvidia   # ← このPCでは動かない
```

**このPCの RTX 5080 は Blackwell 世代（compute capability 12.0 / sm_120）で、
CUDA 12.1 ビルドの PyTorch には sm_120 のカーネルが入っていない。**
入れても `torch.cuda.is_available()` が True になったまま、実行時に
「no kernel image is available for execution on the device」で落ちる。

**README・`docs/使い方.md`・`environment.yml` の3つは直してある**
（世代ごとの必要な CUDA の対応表と、`get_arch_list()` で確かめる手順に置き換えた）。
Windows PC と Mac にも関わる変更なので、pull したら目を通すこと。

このPCでは **`environment.yml` をそのまま作るだけでよい。** conda-forge の
`torchvision` が CUDA 13.0 ビルドの `pytorch 2.13.0` を連れてくる。

```bash
conda env create -f environment.yml
conda activate dc5
```

入ったもの。

```
torch 2.13.0   cuda build 13.0
arch list: sm_75 sm_80 sm_86 sm_90 sm_100 sm_110 sm_120 compute_120
```

`sm_120` が入っているので RTX 5080 で動く。**追加の pip install は要らない。**

確認コマンド。

```bash
python -c "import torch; print(torch.cuda.get_arch_list())"   # sm_120 があること
python -m dc5lib.device                                        # cuda が選ばれること
```

`DC5_MACHINE` は conda の activate.d に入れてある。`conda activate dc5` した
シェルでは自動で `lab-ubuntu` になる。

```
~/anaconda3/envs/dc5/etc/conda/activate.d/dc5.sh
    export DC5_MACHINE=lab-ubuntu
```

`DC5_DATA` と `DC5_SSD_ID` は**設定していない。** SSD A を挿すだけで
`dc5lib.paths` が `/media/hirokanezemi/SSD-PHPU3A/dc5-data` を自動検出する。
SSD を2台挿したときだけ `export DC5_SSD_ID=A` を足すこと。

## 3. 直したバグ — `dc5lib/paths.py`

Ubuntu には root 専用の `/media/root/` があり、一般ユーザーからは
stat もできない。`find_data_roots()` の `consider()` が `p.is_dir()` を
try の外で呼んでいたため、`python -m dc5lib.paths` が
`PermissionError: /media/root/dc5-data` で落ちていた。

`is_dir()` を try の中に入れて、読めないマウントは飛ばすようにした。
**Ubuntu 固有の問題なので、Mac と Windows には影響しない。**

## 5. 気をつけること

**パッケージのメジャーバージョンが上がっている。** conda-forge の最新を取るので、
Windows PC / Mac と数字が揃わない可能性がある。

```
python 3.11.16 / numpy 2.4.6 / pandas 3.0.6 / opencv 5.0.0
torch 2.13.0 (cu13.0) / torchvision 0.28.0
```

ノートブックが使う API（`torchvision.transforms.functional` の
`hflip` / `affine` / `InterpolationMode`、`sklearn.model_selection.train_test_split`、
`scipy.ndimage.gaussian_filter` / `label`）は全部そのまま動くことを確認済み。
分割の再現性も `random_state=42` で保たれている。

**RAM が 31GB しかない。** `hirosima_sam_apm_geo_final_v2.pkl` は 6.9GB あり、
3入力の条件を動かすときは広島と島根を同時に開かないこと。

**`/` の空きが 20GB しかない。** 重み・キャッシュは全部 SSD 側に出るので普段は
問題ないが、リポジトリを SSD 上に clone し直したりしないこと（README の警告どおり）。

## 6. VS Code

拡張は入っていた（`ms-python.python` / `ms-toolsai.jupyter` / Pylance）。

`.vscode/` は `.gitignore` で除外されている = **各PCで別の設定を持つのが正しい。**
このPCには次の2つを置いた。

- `settings.json` … 既定のインタプリタを dc5 に固定、`PYTHONPATH` にリポジトリ直下を
  追加（ノートブック以外からも `import dc5lib` が通る）、`DC5_MACHINE=lab-ubuntu`、
  `results/evals/`（397件）を検索対象から除外
- `launch.json` … `paths` / `registry` / `check` / `run_inference` / `run_instance_eval` /
  `run_analysis` / `make_metrics` を F5 から流せる。地域と条件名は実行時に聞かれる

ノートブックを開いたら、右上のカーネルで **「Python (dc5)」** を選ぶ。
